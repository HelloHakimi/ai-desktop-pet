# AI 桌宠

一只住在桌面上的 AI 宠物：透明置顶的无边框窗口 + Live2D 形象 + 大模型对话。

当前进度：**里程碑 1（可运行骨架）与里程碑 2（对话接入）都已完成**。
骨架的含义是「壳必须是活的」——窗口行为、形象渲染、配置系统、模型接入的分层都已经打通并可替换；
里程碑 2 在此基础上接上了真正能聊的对话：托盘开一个独立对话窗口、流式回复、
形象头顶的气泡、会话存盘与上下文裁剪。后续计划见文末路线图。

## 日常使用：装成 App

桌宠是要常驻的东西，不该每次开终端跑。打成 macOS 应用只需要一条命令：

```bash
# 国内网络建议带镜像：Electron 二进制默认从 GitHub Releases 拉，实测只有 ~100 KB/s，
# 不带镜像装一次要十几分钟。下载后仍会用官方 checksums.json 校验完整性。
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install

npm run setup:live2d           # 首次：取 Cubism Core（官方单独分发，仓库不含）
npm run dist                   # 产物：dist/mac-arm64/AI 桌宠.app
cp -R "dist/mac-arm64/AI 桌宠.app" /Applications/
```

之后双击「AI 桌宠」就能用。**操作入口只有菜单栏那个爪印图标** —— 应用刻意不显示 Dock 图标
（`window.hideDockIcon`），所以「退出」也在托盘菜单里，别去找 Cmd+Q。

托盘菜单里还有一个「登录时自动启动」，勾上就开机自启（这项只在打包后出现，
开发模式下注册的会是 node_modules 里的 Electron 可执行文件，没有意义）。

> 应用是本地构建的，没有签名也不影响双击运行。但要**发给别人**得先签名 + 公证，
> 或者让对方右键 →「打开」绕过 Gatekeeper。

## 开发

```bash
npm install
npm run dev        # 带热更新
npm run build      # 只构建到 out/
npm run preview    # 用构建产物启动（不打包）
```

启动后你会看到：

- 屏幕上一只 **Live2D 形象「Q版 A」**（透明背景、无边框、始终置顶，可拖动，目光会跟着鼠标走，
  每 4–8 秒还会随机眨一次眼，点一下会有反应）
- 菜单栏托盘里有一个**爪印图标**，右键可打开菜单
- 托盘菜单里的**「聊聊天」**可以开/关对话窗口（关掉窗口不会打断正在生成的回复，会转到气泡里继续说）

> 形象资源在 `src/renderer/public/models/qpet-a/`。缺 Cubism Core 时（新克隆的仓库）会自动降级为
> 内置的占位小宠物，并说明原因 —— 这是刻意设计的降级路径，见下方「启用 Live2D」。

托盘菜单提供：显示/隐藏、聊聊天、清空对话历史…、始终置顶、点击穿透、切换形象、试个表情、敲琴、
重新加载形象、打开配置文件、登录时自启、退出。

形象上挂的那些表情（情绪、眼镜、奶茶、敲琴…）不是手动点了才出现 —— 聊天内容、鼠标点按与拖拽、
闲置与深夜都会触发它们，规则与映射表见下方「[表情与触发](#表情与触发)」。

## 打包细节

`electron-builder.yml` 里有三个刻意的选择：

**不用 asar。** 主进程里所有资源路径都是相对 `__dirname` 定位的（`../renderer`、`../../resources`），
打了 asar 就得再写一套指向 `app.asar.unpacked` 的路径改写，换来的只有「文件看起来整齐一点」。
副作用正好是想要的：模型文件在 `.app` 里是散的，想换模型直接丢进
`Contents/Resources/app/out/renderer/models/` 就行，不用重新打包。

**`node_modules` 一律不进包。** pixi 这些已经被 Vite 打进 renderer 的 chunk 了，
再带一份只是白占空间（本地 `node_modules` 有 440 MB）。所以包里的 `Contents/Resources/app/`
只有 `out/`、`resources/` 和 `package.json` —— 这也是为什么图标脚本要用标准库写：
构建链上每多一个依赖，就多一个「换台机器跑不起来」的理由。

（`package.json` 里现在**连 `dependencies` 键都没有**：三个运行时库全部已打进 chunk，
留在 `dependencies` 只会让 electron-builder 以为需要把它们拷进包。）

**关掉签名**（`identity: null`）。本机 `security find-identity` 是 0 个有效身份，
不显式关掉的话 electron-builder 会尝试签名然后报错。

应用图标由 `npm run make:icon` 生成（`build/icon.icns`）。它和托盘图标共用同一套爪印几何，
所以两处图形是一致的。产物已入库，改了设计再跑一次。

### `npm run dist` 卡在 packaging 不动？

大概率不是构建出问题，而是 electron-builder 在**下载 Electron 二进制**时卡住了
（国内直连 GitHub Releases 常常卡在拉 `SHASUMS256.txt` 那一步，甚至不报错、就这么挂着）。
判据：`dist/` 迟迟不出现，进程 CPU 接近 0，也没有 `dist/builder-effective-config.yaml`。

用镜像重跑即可（下载后仍会用官方 `checksums.json` 校验完整性）：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm run dist
```

注意镜像会改变 `@electron/get` 的缓存键（缓存目录是按下载 URL 的哈希命名的），
所以切换镜像后第一次仍会真的重新下载一次。

另外 electron-builder 的校验和它**从不使用缓存**，每次打包都要重新拉一次 `SHASUMS256.txt` ——
所以网络抖动会反复咬人，这不是配置问题。实测同一个命令在几分钟内一次成功、一次挂满 10 分钟。

## 配置

配置文件在 userData 目录，首次启动自动生成：

| 平台 | 路径 |
| --- | --- |
| macOS | `~/Library/Application Support/ai-desktop-pet/pet.config.json` |
| Windows | `%APPDATA%/ai-desktop-pet/pet.config.json` |
| Linux | `~/.config/ai-desktop-pet/pet.config.json` |

托盘菜单的「打开配置文件…」可以直接打开它。完整示例见 `pet.config.example.json`。

优先级：**环境变量 > 配置文件 > 默认值**。写错的字段会被忽略并回退默认值，而不是让应用崩掉。

环境变量：

| 变量 | 说明 |
| --- | --- |
| `PET_API_KEY` | API Key（也可用 `OPENAI_API_KEY`） |
| `PET_BASE_URL` | 兼容 OpenAI 的 baseUrl（也可用 `OPENAI_BASE_URL`） |
| `PET_MODEL` | 模型名 |
| `PET_CONFIG` | 指定配置文件路径，方便同时养好几只 |

**有三样东西会自己写回配置文件**（都走同一个「只动点名的那一节、原子写、其余字段原样保留」的函数）：

| 写回时机 | 写什么 |
| --- | --- |
| 托盘「切换形象」 | `model.path` / `model.idleMotionGroup` |
| 托盘「始终置顶 / 点击穿透」 | `window.alwaysOnTop` / `window.clickThrough`（所以重启后保持） |
| 拖动形象松手 | `window.x` / `window.y`（下次启动就摆回这里；坐标落在已经拔掉的显示器上时会被忽略，见「已知限制」） |
| 托盘「主动说话」 | `assist.companion`（快捷方式：这个开关也可以在配置里改，两边是同一个值） |
| 托盘「系统事件」 | `assist.systemEvents`（同上，菜单勾与配置是同一个值） |
| 托盘「闲聊」 | `assist.smalltalk`（同上。陪玩不看这个开关 —— 那是你叫它，不是它自己开口） |

## 启用 Live2D

形象已经在仓库里了（1 个，4.2 MB），只需要补一步：获取 Cubism Core。

```bash
# Cubism Core 由官方单独分发（有再分发限制），仓库不含此文件
npm run setup:live2d
```

装好后从托盘菜单点「重新加载形象」即可生效，**不用重启** —— 渲染层不会把「缺少 Core」这个
失败结果缓存下来，就是为了让这条最自然的路径走得通。

`model.mode` 支持三种取值 ——

- `auto`（默认）：能跑 Live2D 就跑，否则静默降级为占位形象
- `live2d`：强制 Live2D，失败时把原因直接显示在窗口上（不静默降级）
- `placeholder`：强制使用占位形象

只支持 Cubism 4/5（`.model3.json` + `.moc3`），Cubism 2.1 的 `.model.json` 未接入。

### 切换形象

托盘菜单 →「切换形象」→ 选一个。选中项前面会打点，选择会写回配置文件，重启后保持。

菜单里的形象是**每次打开菜单时扫目录**得到的，不是在代码里写死一份列表 ——
往模型文件夹里丢一个新模型，不用改代码、不用重新构建、不用重启，菜单里就会出现。
（「切换形象 → 打开模型文件夹…」可以直接在访达里打开那个目录。）

仓库里现在只有 1 个形象：

| 目录 | 菜单显示名 | 贴图 | 动作 | 表情 | 大小 |
| --- | --- | --- | --- | --- | --- |
| `qpet-a/` | Q版 A | 1×2048 | 12 | 40 | 4.2 MB |

每个模型目录里的 `pet-model.json` 决定菜单里显示的名字和待机动作组名：

```json
{ "name": "Q版 A", "idleMotionGroup": "Idle" }
```

改这个文件就能改名，不用碰代码（改完点一下托盘里的「重新加载形象」，菜单会重扫目录）。

**配置指着的形象不见了怎么办？** 启动时会检查一次 `model.path` 是否真的存在，不存在就自动改指到
一个确实存在的形象并写回配置文件，同时打一行警告。这不是多余的防御 —— 形象清单是**扫目录**得到的，
删掉一个模型目录之后配置文件里还留着旧路径，不修的话启动后托盘里是一组**全都没打勾**的单选项，
而窗口上只有一句「模型文件不存在」，用户根本不知道该点哪个。
（只在启动时修，不在 `loadConfig()` 里修：那个函数被很多地方调用，不该带写文件的副作用。）

### 试个表情

托盘菜单 →「试个表情」→ 选一个。列出的是**当前形象** `model3.json` 里登记的表情，
所以换个形象菜单就跟着换（当前这个形象有 40 个）。末尾还有两项：

- **随机一个** —— 从当前形象的清单里随机套一个（不会抽到敲琴的按键图案，抽出来只会让人以为游戏开始了）
- **还原默认** —— 清掉所有表情层，回到默认脸

**勾画的是渲染层报上来的真实状态**，所以：

- 每个表情都是复选框语义，**再点一次就是取消**（原始 `.vtube.json` 里这些表情登记的就是
  `ToggleExpression`，这个语义反而是模型作者的本意）
- 表情是**分层叠加**的，所以可以同时有多个勾 —— 「墨镜 + 奶茶 + 戴帽子」会同时打三个勾，
  一眼能看出它现在戴了什么（机制见下方「[表情与触发](#表情与触发)」）
- 随机、限时到期的表情、切换形象之后的清空，勾都会跟着变；「重新加载形象」时先手清一次勾，
  免得重建那一两秒里勾还停在旧状态上

表情名原样取自 `model3.json`，不做任何美化 —— 这个名字和文件名**不保证一致**：

| 菜单里的名字 | 实际指向的文件 |
| --- | --- |
| `右键` | `左键.exp3.json` |
| `左键` | `真 左键.exp3.json` |
| `大哭` | `哭.exp3.json` |
| `举喇叭` | `拿喇叭.exp3.json` |
| `我会出手` | `打拳.exp3.json` |

（名字里也可能含空格，所以渲染层的「还原默认」用的是可辨识联合而不是空字符串哨兵。）

表情文件是**按需加载**的，第一次套用某个表情要现取一次 `exp3.json`；之后由
`ExpressionDefs` 自己缓存，命中缓存后只剩每帧写参数的开销。

顺带说一句：这 40 项里有 7 个不是情绪表情，而是**按键叠加层** ——
`A` `S` `D` `W` `左键` `右键` `1`。这个模型带一个敲琴小游戏，按哪个键就显示对应图案
（用法见「[敲琴](#敲琴)」）。另外 `1` 与 `猫球` 的 exp3 写的是同一个参数
（`ParamCheek34 = 1`），所以这两个名字是同一张画面 —— 40 个名字实际只有 39 种样子。

### 遮掉某个部件（比如翅膀）

配置里的 `model.hiddenParts` 填部件 id 就能遮掉它们，只影响显示 —— 模型文件一个字都不动，
清空这个数组就恢复：

```json
"model": {
  "hiddenParts": ["Part12"]
}
```

渲染层每帧在 `beforeModelUpdate`（所有参数/部件写入者之后）把这个部件的透明度压到 0。
**必须每帧写**：部件透明度是动作和表情的写入对象，设一次是留不住的，待机动作下一轮就把它写回来。
当前形象 `qpet-a` 的翅膀是 `Part12`（那对白羽毛翼，两层共 4 个 ArtMesh）。

**怎么找部件 id**：别信 `.cdi3.json` 里的名字 —— 这个模型的 `Part12` 在 cdi3 里登记的名字是
「马尾R」，而名字叫「翅膀L」「翅膀R」的 `Part43`/`Part39` 底下**一个 ArtMesh 都没有**。
只能看运行时的实际归属：给应用加调试端口，在 Chrome 的 `chrome://inspect` 里附加到形象页面，
Console 里跑

```js
const cm = queryObjects(PIXI.Application.prototype)[0].stage.children[0].internalModel.coreModel
const ids = cm._model.parts.ids, cnt = {}                       // 每个部件实际画了几个东西
for (let i = 0; i < cm.getDrawableCount(); i++) cnt[cm._model.drawables.parentPartIndices[i]] = (cnt[cm._model.drawables.parentPartIndices[i]] ?? 0) + 1
ids.forEach((id, i) => cnt[i] && console.log(id, cnt[i]))
cm.setPartOpacityById('Part12', 0)                              // 试一下：这一帧就看不见了
```

`hiddenParts` 是跨形象复用的：换形象之后 id 大概率对不上，那时渲染层只打一行警告并跳过，
不会报错、也不会把形象画坏。另一处坑是 `getPartIndex()` 查不到时返回的是 **NaN 而不是 -1**，
所以校验写的是 `Number.isInteger(index)`（写 `index < 0` 会让 NaN 溜过去，然后无声地失效）。

### 装一个新模型

模型大多是给 VTube Studio 用的，直接拷过来会得到一个不会动、不眨眼、表情全空的花瓶 ——
动作和表情登记在 `.vtube.json` 里，而 `pixi-live2d-display` 不读那个文件。
`scripts/install-model.py` 负责把这层信息搬过去：

```bash
python3 scripts/install-model.py <源模型目录> <目标目录名> --name "菜单里的名字"
# 例：python3 scripts/install-model.py /tmp/extract/MyModel my-model --name "我的形象"
```

它做四件事：只挑运行时需要的文件复制（跳过 UI 图、插画、psd、图标）→ 调
`downscale-textures.py` 降采样贴图 → 从 `.vtube.json` 补全 `model3.json` 的
`Motions` / `Expressions` / `Groups` → 写 `pet-model.json`。中途失败会把半个目录删干净，
不会在托盘里留一个加载不出来的残骸。

源目录里的文件名建议是 UTF-8。从 GBK 编码的 Windows 压缩包里解出来的话，
用 `ditto -x -k` 或 Python 的 `zipfile` 显式按 GBK 解码，别用 `unzip`（会解出乱码文件名）。

### 这几份模型都补了什么

它们原本都是给 VTube Studio 用的，动作和表情登记在各自的 `.vtube.json` 里，而这份文件
**`pixi-live2d-display` 不读**。所以每个 `model3.json` 都被补齐了三处，否则模型只是不会眨眼、
不会动、也没有表情的静态立绘：

| 补的内容 | 来源 | 作用 |
| --- | --- | --- |
| `FileReferences.Motions.Idle` | vtube 的 `FileReferences.IdleAnimation` | 循环待机动作 |
| `FileReferences.Motions.Tap` | 其余 `*.motion3.json` | 打包成一组，留给将来「点击随机播一个」 |
| `FileReferences.Expressions` | vtube 的 `ToggleExpression` 热键表 | 让 `setExpression('哭哭')` 这类调用能找到表情 |
| `Groups` 的 `EyeBlink` / `LipSync` | vtube 参数表里 `Input` 为 `EyeOpen*` / `MouthOpen` 的项 | 让它会眨眼；口型留给里程碑 3 |

`Idle` 这个组名不能改：`pixi-live2d-display` 内部用 `groups.idle = "Idle"` 识别待机动作，
换成别的名字它就不接管了。

对 `model3.json` 的改动是**纯增量**的（只加不改原有字段），想回到原版把 `Motions` /
`Expressions` / `Groups` 三段删掉即可。原始压缩包在 `~/.Trash/` 里（早先那批形象已经从仓库里去掉，
但仍然留在 git 历史里，需要时 `git show <commit>:<path>` 就能取回来）。

### 贴图降采样：从 4096/8192 降到 2048

这批模型自带的贴图是 4096²，`Q版` 那两个更是 **8192²** —— 单张 8192² 解码后就要 256 MB 显存。
`桃瑟古风` 一家有 14 张贴图，原样加载约 896 MB。形象只渲染在 320×460 的窗口里，
这些分辨率有一大半是白解码、白占显存。

```bash
python3 scripts/downscale-textures.py <模型目录> 2048
```

下面这组对比是在仓库里还有 `blue-cat` 的时候测的（同机同配置，只改贴图分辨率），
降采样的理由和幅度对现在的 `qpet-a` 同样成立：

| | 4096（原始） | 2048（当前） |
| --- | --- | --- |
| 合计常驻内存 | 924 MB | **582 MB** |
| 渲染进程 | 593 MB | 305 MB |
| GPU 进程 | 145 MB | 90 MB |
| 贴图文件体积 | 21.7 MB | 7.2 MB |

画质验证方式是**先把待机动作和眨眼冻住**再逐像素比 —— 第一版对比得出「15% 像素不同」是假象，
那比的是动画的不同帧，不是画质。冻住之后：平均通道差 1.14/255，差异集中在轮廓的亚像素抗锯齿，
3 倍放大目视无可见差别。

## 表情与触发

形象上的表情不是「点了才有」，而是由四类触发源自动驱动：聊天内容、鼠标、生命周期、闲置。
这一节讲清机制与映射，改规则时不用来回翻代码。

### 分层机制：为什么不用库的表情槽

`pixi-live2d-display` 的 `model.expression(name)` 是**单槽**语义（一个 `currentExpression`，
新的顶掉旧的），而这个形象的 40 个表情里绝大多数参数互不重叠 —— `ParamCheek70` 是圆眼镜、
`Cheek44` 是帽子、`Cheek16` 是星星眼、`naicha` 是奶茶。单槽等于白白丢掉组合，
而「墨镜 + 奶茶 + 生气脸」才是它像个活物的关键。

所以表情由我们自己读、自己写：

| 环节 | 在哪 | 做什么 |
| --- | --- | --- |
| 读定义 | `pet/expressionDefs.ts` | 从 `model3.json` 取「名字 → exp3 文件」，按需 fetch 并缓存；解析 `Parameters`（`Id` / `Value` / `Blend`），当前模型没有的参数直接丢掉 |
| 分层调度 | `pet/expressionDirector.ts` | 谁现在挂着、通道归属、限时回落、互斥、每帧写参数 |
| 每帧写入 | `Live2DRenderer` 的 `beforeModelUpdate` | 与眨眼、遮部件同一个窗口：库里所有写入者之后、求值之前 |

三个关键约束：

- **每帧重写**。写一次留不住 —— 动作（待机/呼吸/目光）下一帧就把参数覆盖回去了。
  这也是为什么这里和 `model.hiddenParts` 一样挂在 `beforeModelUpdate` 上。
- **写入顺序：表情 → 眨眼 → 遮部件**。注册顺序即执行顺序，不能调换：眨眼是按「当前睁眼度」做
  乘法修饰，它必须看到表情层写完的结果（否则 `墨镜` 那种把眼睛压到闭合的表情会在眨眼时被反着拉开）。
- **`Blend` 照抄**。这个模型的 40 个表情全部标的是 `"Blend": "Add"`，值与基准值**相加**才是它们
  的设计语义（`晕晕` 的 `ParamEyeLOpen = -0.5` 是「闭一半」而不是「把睁眼度设成 -0.5」）。
  照抄 Blend 才能让「试个表情」和以前用库套出来的一模一样。

### 通道：谁能和谁叠

每个表情名归属一个通道，通道决定「能不能同时挂着」：

| 通道 | 单槽 / 可叠 | 成员 | 叠加效果 |
| --- | --- | --- | --- |
| `emotion` | 单槽 | 开心兴奋、星星眼、爱心眼、脸红、调皮、生气、悲伤、大哭、晕晕、阴暗、呆呆眼、闭眼口水、问号、感叹号、情绪花花、心跳、流汗、吐魂 | 新的顶掉旧的 |
| `glasses` | 单槽 | 圆眼镜、方眼镜、椭圆眼镜、墨镜 | 四副眼镜戴一副 |
| `prop` | 单槽 | 奶茶、猫球、圆木桌、举喇叭、爆肝、我会出手 | 手里/身边只能有一件道具 |
| `decor` | **可叠** | 戴帽子、兔兔贴纸、猫猫贴纸、蝴蝶结贴纸 | 帽子 + 贴纸可以同时戴 |
| `piano` | 单槽 | 手敲琴 | 由敲琴模式控制 |
| `key` | 单槽 | A、S、D、W、1、左键、右键 | 按键图案，压在所有层之上 |

同一参数被多层写到时，**通道顺序靠后的赢，同通道里后调用的赢**（顺序：decor → glasses → prop →
piano → emotion → key → misc）。参数实测出来的互斥关系只有一对：`举喇叭` 的 exp3 会把敲琴的参数
清零（`ParamCheek33 = 0`、`ParamCheek3 = 0`），所以这两个互相排斥。

表里没有的名字落到 `misc`（单槽）—— 换个形象也能照常用，只是不会分层。

**不做淡入淡出**是刻意的：桌宠的反应要「啪」的一下才像活的，而过渡会引入「上一层的权重还没退干净
又要叠新层」的插值状态，那是这套东西里最容易写出鬼影的地方。库自带过渡，但那是单槽语义。

### 触发源一：聊天内容（本地关键词）

`main/chat/emotion.ts`。判定的输入是**用户说的话**，不是它的回复 —— 这只宠物先对你说的有反应，
再开口回你。**没有用「让模型打情绪标签」那套**，原因很直接：那要给 systemPrompt 加一套输出格式约束，
还要在流式管道里扣住开头的标签、决定哪些字先不吐给界面，为了一张脸不值得把最稳的那条链路改复杂。
关键词判定零成本、零延迟、判错了改一行。

规则是**有顺序的**，两轮 + 兜底，先命中的赢：

1. **情绪词**（挂 3.5 秒，单槽）——「工作好累」该是难过，而不是摆一张桌子出来，所以情绪优先
2. **配件道具词**（挂 60 秒，可叠）—— 「陪你做这件事」得挂久一点才像那么回事
3. **兜底**：疑问句 → `问号`；两个字以内的短消息（「嗯」「哦」）→ `呆呆眼`
4. 都不命中 → **不动脸**。大部分普通消息本来就不该让桌宠变脸，一直乱变才是噪音

| 说什么 | 表情 | 说什么 | 表情 |
| --- | --- | --- | --- |
| 骂它（讨厌/笨/滚） | 生气 | 夸它（好可爱/厉害/崇拜） | 脸红 / 星星眼 |
| 表白（喜欢你/爱你） | 爱心眼 | 开玩笑（嘿嘿/你坏） | 调皮 |
| 倾诉（难过/累了/emo） | 悲伤 → 大哭 | 报喜（恭喜/生日快乐） | 情绪花花 |
| 求助（帮我/怎么办/救命） | 我会出手 | 加班熬夜 | 爆肝 |
| 想喝奶茶 / 饿了 | 奶茶 | 写代码 / bug | 方眼镜 |
| 看书 / 读书 | 圆眼镜 | 上班 / 出门 / 好冷 | 戴帽子 |
| 提到猫 | 猫猫贴纸 | 唱歌 / 弹琴 | 手敲琴 |
| 晚安 / 睡了 | 闭眼口水 | 打扰了 / 尴尬 | 流汗 |

判出来的名字会先跟**当前形象的表情清单**对一遍：换个形象之后「奶茶」可能根本不存在，
那时候每次都往渲染层发一个不存在的名字，只会刷一堆警告。

### 触发源二：鼠标

判定全在渲染层本地（`pet/interaction.ts`），主进程只收一条「用户碰了形象」的消息用来重置闲置时钟。

| 动作 | 反应 | 说明 |
| --- | --- | --- |
| 单击 | 反应池随机一个（调皮/星星眼/脸红/心跳/开心兴奋/爱心眼） | 挂 1.5 秒 |
| 连点 3 次 | 生气 | 1.6 秒内数够 3 次；间隔太短的点击只压掉换脸，不影响计数。**气头上再点只续上它**（重新计 1.6 秒），不会换回反应池随机 |
| 拖动 | 晕晕 | 位移一过阈值（拖动真的开始）就挂上、拖多久晕多久，松手后再留 0.8 秒；拖动过程中不算抚摸 |
| 抚摸（来回划） | 脸红 →（再来一轮）爱心眼 | 1.2 秒内 3 次方向反转算一轮，一轮数一次；两轮之间停手超过 1.2 秒就从头数 |
| 闲置 5 分钟 | 闭眼口水（深夜是阴暗） | 醒了只摘掉这张脸，不动别的层 |
| 敲琴模式下的左右键 | 左键 / 右键 图案 | 模型自带的按键层 |
| 双指轻点 / 右键（= 辅助点按） | 收起桌宠 | 点在形象上才算；敲琴时这条让位给「右键」图案 |

**双击形象不再有特殊行为**（曾经是开气泡输入框，2026-09-20 去掉了，见下）。

### 触发源三：生命周期

| 时机 | 表情 |
| --- | --- |
| 形象挂载成功（启动、换形象、重新加载） | 星星眼（2 秒）—— 等于「我来啦」 |
| 生成被「停止」 | 问号 |
| 生成失败（网络异常或 HTTP 401/500） | 流汗 |
| 清空对话历史 | 吐魂 —— 记忆清零，灵魂出窍 |

### 触发源四：闲置与深夜

主进程的闲置时钟（`main/idle.ts`）：5 分钟没有任何交互（发消息、点形象、动托盘菜单都算）就切到
`闭眼口水`；23:00–6:00 之间切到 `阴暗`。醒来只摘掉打盹的那张脸 —— 用户手动套的眼镜不该因为
打了个盹就消失。敲琴时不打盹（用户正在玩）。

### 敲琴

托盘菜单 →「敲琴」。模型自带 7 个按键叠加层表情与一套敲琴动作，这个模式把它们连起来：

- 进来先挂上 `手敲琴`（模型自带的小木琴与两根琴槌）
- 键盘 **A S D W 1** 各对应一个按键图案与一个音高（五声音阶 C5 D5 E5 G5 A5），
  用 WebAudio 现场合成，不带音频资源
- 点形象 = `左键` 图案，右键 = `右键` 图案
- **Esc 退出，或在托盘里再点一次**（状态会回报给主进程，托盘的勾跟着走）

**入口只在托盘**，因为进来要**抢键盘焦点**：键盘事件只会送到有焦点的窗口，而桌宠平时是点击穿透、
不抢焦点的。一个桌宠随手抢走用户正在打字的键盘不能接受，所以这必须是一个用户明确发起、
又能一眼找到退路的动作。点回别的窗口就收不到键了（琴还挂着），点一下形象或托盘重开即可。

### 双指轻点 / 右键：收起桌宠

收起桌宠原来是托盘「显示 / 隐藏」的事，现在在形象上也能收：**双指轻点或右键形象**。

- macOS 的「辅助点按」（双指轻点）在系统层面**就是一个右键事件**，到渲染层已经分不开了 ——
  所以鼠标右键、`⌃`+点按会一起生效。「只认手势、不认右键」做不到，也就没法只给手势。
- 判定用的是和单击同一道门槛（逐像素 alpha 掩码）：点在**被截断的气泡**上、点在形象周围的
  透明处都不收起 —— 那些地方虽然也落在可交互区域内，但用户那时想的不是把桌宠收起来。
- **敲琴时让位**：右键在那个模式下另有含义（模型自带的「右键」按键层），键盘优先 ——
  玩到一半桌宠突然不见了太吓人。
- 收起来之后唯一的回头路还是托盘「显示 / 隐藏」（行为与原来一致）。主进程会留一行
  `[pet] 已收起（双指轻点 / 右键）` 的日志 —— 它消失之后「是被收起来了还是崩了」只能从这里看。
- **开始聊天时它自己回来**：⌥⌘+← 发一句、或按 `⌥⌘↑` 处理剪贴板 —— 这两条路的回复都冒在它头顶的
  气泡上，藏着一只等于白说。回来的方式是 `showInactive`：**不抢焦点**，否则你正在打字的气泡输入框
  会失焦关掉（那个窗口失焦即关）。**助手台词不叫它回来**：久坐提醒、专注到点、系统事件照旧不出声 ——
  把它收起来就是在说「别打扰我」，只有你主动开口才算数。

## 接入大模型

Provider 层是独立的，目前实现了 OpenAI 兼容协议，DeepSeek / 通义 / Kimi / 本地 vLLM / Ollama
都可以直接复用，只改 `ai.baseUrl` 与 `ai.model`。

先做连通性自检（不启动 Electron，把配置问题和 UI 问题分开定位）：

```bash
export PET_API_KEY=sk-xxxx
npm run ai:ping
# 或指定提示词
npm run ai:ping -- --prompt "用一句话夸我"
```

新增厂商：在 `src/main/ai/index.ts` 的注册表里注册一个 `ProviderFactory` 即可，
会话层与两个窗口都不需要改动。

## 和它聊天

两个入口：

- **托盘菜单「聊聊天」** —— 开/关**对话窗口**，形象隐藏时也能用
- **⌥⌘+←** —— 随时召出/收起**气泡输入框**（Dock 上方的 Spotlight 风格纯输入框：`Enter` 发送、
  `Esc` 或失焦关闭、发完保持打开接着聊）。两个入口都是「发出去就把桌宠叫回来」：
  它要是正被收着（双指轻点藏起来了），消息一发它就自己现身 —— 回复冒在它头顶的气泡上，
  藏着一只说给谁听？回来用 `showInactive`，**不抢焦点**（抢了会把气泡输入框挤掉：那个窗口失焦即关）。

> 形象上原本还有「双击开气泡输入框」这条入口，2026-09-20 去掉了：那个输入框会抢焦点
> （`app.focus({ steal: true })`），而点形象本身就是「逗它」的动作、连点两下很常见 ——
> 逗它的时候冒出一个抢走键盘的框很讨厌。要快捷输入走 `⌥⌘+←`，两个入口都是显式的。

对话窗口是**一个常规窗口**（有交通灯、可缩放、可被系统聚焦），因为它要承载输入框和可滚动的消息列表，
不是桌面上的装饰。位置每次打开都贴着形象重新算 —— 不记忆「上次拖到哪」，用户永远知道开窗之后窗
口会出现在哪。键盘：`Enter` 发送、`Shift+Enter` 换行、`ESC` 只关窗（**不打断**正在生成的回复）。

生成是**流式**的：回复边说边出现，期间发送键变成「停止」。

### 形象头顶的气泡

回复在对话窗口里显示的同时，也会在形象头顶的气泡里**同步说一遍**。这是关掉窗口之后唯一的反馈通道 ——
所以关窗不打断生成，剩下的半句话会继续在气泡里说完。

- 气泡只留前 60 个字（原文长的话截断加省略号），全文在对话窗口里
- 说完停留 8 秒后自动淡出；**鼠标停在气泡上则暂停计时**（正在读的话不该被收走）
- 出错时气泡转成红调提示，和对话窗口里的错误提示是同一个色
- 气泡是 `pointer-events: none` 的纯展示元素：它浮在形象头顶，一旦能收鼠标事件，
  命中判定和拖动就会把「鼠标在气泡上」当成「鼠标在形象上」
  （唯一的例外是下面那排提问按钮，它单独把指针事件要回来）

### 气泡里的选项按钮

气泡底下有时会挂一排按钮（最多 3 个）：点名、出拳、回答「吃了没」，点一下顶打一句话。
按钮是**主进程挂的**（`main/ask.ts` 记账：谁在问、点了第几个怎么办），渲染层只负责画出来、
把「点了第几个 / 没人理」报回去。

三处会用：

| 场景 | 按钮 | 点了之后 |
| --- | --- | --- |
| 碎碎念的**陪玩邀请** | 猜数字 / 猜拳 / 猜表情（这个形象能玩的才出现） | 直接开局，等于打字说了那三个字 |
| **猜拳**每一回合 | 石头 / 剪刀 / 布 | 出拳、报回合，再挂上下一轮的按钮 |
| **午饭问句**（「中午了，吃了没？」） | 吃了 / 还没 | 本地回一句预设的话，不花 token |

四条实现上的约定：

- **按钮挂在气泡当时那句话上**：那句话一换（新回复、新台词、新闲聊），按钮就自动撤 ——
  所以「先说话、再挂按钮」的先后顺序不敏感，也不会出现「问题没了按钮还杵着」。
- **点出来的那一回合和打字完全同路**：进对话窗口、带 `local` 标记、不落盘、不进上下文 ——
  按钮只是省了打字，没有第二条链路。
- **20 秒没人理就整条收掉**（连问题一起），之后不再追问；鼠标停在气泡上时暂停计时。
  主进程另有一道 30 秒兜底：渲染层万一没把下线报回来，那个槽也不会被永久占住。
- **挂着按钮的气泡整块可交互**（点击穿透退让），和「被截断的气泡」同一套命中机制；
  这一刻双击气泡也不再开对话窗口 —— 该点的是按钮。

打字那条老路全部保留：邀请后回一句「好」、动手打「石头」，都照旧接得住。

### 会话与存盘

**只有一份连续对话**（不做多会话），它住在主进程里，和配置文件放在一起：

| 平台 | 路径 |
| --- | --- |
| macOS | `~/Library/Application Support/ai-desktop-pet/chat-history.json` |
| Windows | `%APPDATA%/ai-desktop-pet/chat-history.json` |
| Linux | `~/.config/ai-desktop-pet/chat-history.json` |

跟配置同目录而不是写死在别处，是为了配合 `PET_CONFIG` —— 用环境变量养好几只桌宠时，
每只的对话历史也跟着各自的配置走。写盘是**原子**的（先写 `.tmp` 再 `rename`），
避免写到一半崩溃留下半个 JSON。

关掉对话窗口、切换形象都不影响会话；重启应用会接着上次聊。

### 上下文管理

`ai.contextLimit`（默认 20，夹取 2–100）控制**每次发给模型的最近消息条数**：
超出时只发最后 N 条，systemPrompt 仍然注入在最前。它**不影响存盘与显示** ——
历史一直留着，界面上能看到全部，只是老消息不再发给模型。

### 模型知道桌宠此刻的样子

发出去之前，会往人设后面接一句当前状态，例如：

```
你是一只住在用户桌面上的小宠物，说话简短、俏皮、有温度，每次回复不超过两句话。

【你现在的状态】挂着的表情/配件：墨镜、生气。
回应用户时可以自然地把这个状态带进去（比如正生着气就别装作没事），但不必每次都提，也不用向用户解释这些是什么。
```

不接这句的话，它会在自己瞪着一脸怒气符号的时候若无其事地回「你好呀」，割裂感很明显。

状态来自三处，**两处是主进程自己就知道的**，只有表情层是渲染层报上来的：

| 来源 | 说什么 |
| --- | --- |
| `runtime-state.ts` 的渲染层上报 | 挂着的表情/配件（`生气`、`墨镜`、`奶茶`…） |
| `focus.ts` | 正陪着用户做一件要专注的事 |
| `idle.ts` 的 `sleepingFace` | 刚才在打盹，被这一句叫醒了 |

两个实现上的要点：

- **「刚才在打盹」必须在 `noteActivity()` 之前读。** 那句话就会把它叫醒，问晚了永远是否。
- **这条消息刚触发的情绪要手动补上。** 渲染层的上报是 400ms 一次，而 `detectEmotion` 的结果
  主进程当下就有 —— 不补的话，「你骂了它」这一轮它还不会有反应，得等到下一轮。

刻意**不**写进去的：敲琴的键位层与点击图案（`A S D W 1`、`左键`、`右键`）—— 那是按下即出现、
松手就淡出的即时反馈，不是「它现在是什么样子」；键位名单直接从 `PIANO_KEYS` 取，
免得和实际听键的代码分家。

也刻意不写**剩余时间、当前时刻**这类一直在变的东西：提示词一变，上游的上下文缓存就整段作废。
状态只在真的发生变化时才会变，所以大多数轮次里这段提示词是稳定的。

带 `systemOverride` 的任务轮次（选中即处理）**不接**这一句 —— 那些要的是干净的指令，不是角色状态。

### 清空

两个入口，都会清掉历史文件并通知所有窗口：

- **对话窗口顶部栏的「清空」** —— 点一下变「确认清空」，再点才真删（4 秒后自动解除）
- **托盘「清空对话历史…」** —— 原生确认弹窗（托盘菜单是一点就走的路径，不能没有这一步）

### 不花钱先试一下

没有 API Key 也能把对话链路跑通：仓库自带一个假的 OpenAI 兼容端点，

```bash
npm run ai:fake                                        # 起在 127.0.0.1:8787
PET_BASE_URL=http://127.0.0.1:8787/v1 PET_API_KEY=fake npm run dev
```

它会按用户消息里的关键词分支：含 `SLOW` 就每 250ms 吐一段（用来看流式与「停止」），
含 `LONG` 吐约 90 字（用来看气泡的 60 字截断），含 `ERR` 直接回 401、`ERR500` 回 500
（用来看错误路径），其余照常回一句固定的话。每个请求还会把「收到的消息条数与角色序列」
打到 stdout —— 核对上下文裁剪时不用猜。

## 小助手

桌宠身上带了几件小工具，入口都在托盘（`处理剪贴板` 另有一个全局快捷键）：
**选中即处理**、**剪贴板历史**、**专注计时**、**主动说话**、**系统事件**、**闲聊**。
陪玩（点单、小游戏）没有菜单项 —— 直接跟它说一句就行，见「陪玩」那一节。

### 选中即处理

复制一段文字 → 按 `⌥⌘↑`（可在 `assist.shortcut` 改，留空即关闭）→ 桌宠把结果说在**气泡**里。

动作是**本地启发式**判的，不额外问模型（多一次往返等于让你对着气泡多等一秒）：

| 内容长什么样 | 做什么 |
| --- | --- |
| 像报错/日志（`Traceback`、`XxxError:`、`at foo (bar.js:12:3)`、`ERROR:` …） | 解释报错：什么问题、最可能的原因、下一步怎么查 |
| 外文为主（汉字占比 < 20%） | 翻成中文 |
| 长文（≥ 800 字，或中文 ≥ 200 字） | 压成 3–5 条要点 |
| 其余 | 改顺一点 |

判错了怎么办：直接在对话窗口里说一句「翻成英文」就行 —— 那一轮还在上下文里，接得上。
所以**不要**指望它是精确的分类器，它只是把最常见的那种活儿猜对。

三条约束写在实现里（`main/assist/`）：

- **不套桌宠人设**：翻译/解释用任务专属的 system prompt（`systemOverride`）。让「你是一只小宠物」
  去翻译，出来的是带卖萌语气的译文，粘进文档还得手动擦；萌那部分交给表情。
- **整轮不落盘**（`ephemeral`）：喂进去的是剪贴板内容，可能是密码、token。这类轮次只存在内存里，
  `saveHistory()` 落盘时统一过滤掉，发给模型前也会把标记摘掉。**过滤放在 store 里而不是各个调用点**，
  因为 `saveHistory` 有六处调用，漏一处就会把剪贴板内容写进磁盘 —— 这个动作得是忘不掉的。
- **上限 3000 字**：超了就在气泡里说「这段太长了」，而不是发一个注定超时或被悄悄截断的请求。

### 剪贴板历史

托盘 →「剪贴板历史」→ 点一条就换回剪贴板。**只存内存，重启即忘** —— 剪贴板里常有密码和 token，
所以这里连一个「要不要落盘」的开关都不提供（没有开关，就没有被写错的配置）。换的时候刻意不说话：
你下一步一定是 `Cmd+V`，粘出来对不对立刻就知道，而每次都让桌宠说一句，用两次就嫌吵。

### 专注计时

托盘 →「专注」→ 25 / 45 / 60 分钟（`assist.focusPresets` 可改）。开始挂 `爆肝`、到点换 `奶茶`
并说一句话；期间每分钟续一次「有人在场」，所以闲置时钟不会把陪你工作的桌宠切去打盹脸。
**刻意不显示倒计时**：番茄钟的意义本来就是别盯着表，真要台面上有个数字，那该走 `tray.setTitle()`
（会改动菜单栏外观，属于用户可见的变化，得先问过）。

### 主动说话（久坐 / 深夜）

默认开（`assist.companion`，托盘可勾）。两句话，都很克制：

- **久坐**：连续在场 90 分钟后提一句，同类提醒 60 分钟内不重复。这里的「在场」用的是
  `powerMonitor.getSystemIdleTime()`（全系统距上次键鼠输入多久），**不是**闲置时钟那个
  `lastActivityAt` —— 后者只记录「和桌宠的互动」，你在别的应用里敲一天代码也不会碰桌宠一下。
  真正离开过 5 分钟，连续计时就清零：午休回来不该立刻收到「你坐太久了」。
- **深夜**：23:30 之后第一次活动提一句，一个晚上只说一次（凌晨那几个小时算**前一天晚上**，
  否则 23:40 问候过之后熬到 00:10 会被再说一遍）。

文案是**预设**的，不走大模型：主动消息要快要稳，不该在你最想安静的时候发来一段 AI 生成的话。

### 系统事件（充电 / 断网）

默认开（`assist.systemEvents`，托盘可勾）。两个信号，都是一张限时脸（2.5 秒）+ 一句话：

| 信号 | 反应 | 为什么挑它 |
| --- | --- | --- |
| 拔电源（`powerMonitor` 的 `on-battery`） | `流汗` +「诶，线掉了？」 | 一天最多几次，零打扰风险，但「它注意到了现实」这件事很值 |
| 插电源（`on-ac`） | `开心兴奋` +「充上啦」 | 同上，和拔电源凑成一对 |
| 断网（连续离线 30 秒） | `问号` +「网没了，先干点别的？」 | 算信息投递：macOS 自己不会告诉你网断了 |

**只做发生在地面上的事。** 锁屏、合盖时屏幕本来就不亮 —— 对着黑屏表演没有意义，
所以没有「你走了」那一侧的反应（也因此砍掉了原本最复杂的那块：判断你离开了多久）。
电量百分比提醒也做不到：`powerMonitor` 只给「拔了/插了」两个事件，不给电量，
想要「低于 20% 提醒」得 shell 出去跑 `pmset` 解析文本，那就不轻了。

三个实现上的决定：

- **断网只能轮询**：主进程只有 `net.isOnline()` 可以问，它没有事件。判定要的是「**连续**离线」——
  切 Wi-Fi、VPN 重连都会闪一下离线，闪一下就说等于谎报。轮询 15 秒，连续离线 30 秒才算数。
  顺带一句官方文档的原话：它返回 `true` 只说明链路起来了，不保证真能连上外网 ——
  所以这信号适合拿来说句俏皮话，不适合当网络诊断。
- **启动时就离线不报**：`offlineTold` 的初值是 `true`，只有亲眼看到过一次在线才会被放开。
  应用刚起来时看到的离线状态不是「刚刚断了」，是它出生时世界的样子，没什么好报的。
- **60 秒内不说第二句**：这条护栏是**跨模块**的（`actions.ts` 的 `msSinceLastSay`），
  久坐提醒、深夜问候、专注到点都算数 —— 深夜问候完下一秒又「拔了电源」，两条都弹出来就像复读机。
  被挡下的那次不排队重试：即时反应晚三十秒再补上，比不说还怪。

### 闲聊（碎碎念 / 招呼 / 饭点 / 节日）

默认开（`assist.smalltalk`，托盘可勾，与上面两个开关并列）。这一层管的是**它自己开口**的那一半：

| 时机 | 说什么 |
| --- | --- |
| 启动后第一次见面（8:00 之后，一天一次） | 「下午好，又是周一……我陪你」—— 节日、纪念日、周五 / 周一 / 周末都接在这一句后面 |
| 锁屏 / 合盖满 10 分钟，解锁回来 | 「你回来啦」，顺手把它叫醒（回来时它多半正打着盹） |
| 12:00 / 18:00（18:00 只在工作日） | 吃饭、下班 —— 到点那一分钟说不成（在专注 / 刚说完话 / 人不在）下一分钟还会再试，过了钟点就等明天 |
| 醒着时的碎碎念（30–60 分钟一次，随机） | 「（画圈圈）好无聊啊……」「突然好想喝奶茶」；一小部分会变成**邀请**：「要不要玩个猜数字？」 |
| 睡着时的碎碎念 | **梦话**：「……再睡五分钟……就五分钟……」（打盹脸不动） |
| 打盹那一刻（45 分钟内只配一次） | 「好困……我先眯一小会儿」 |

「睡着还说梦话」不是矛盾：打盹的节奏按你的选择**保持原样**（5 分钟没人碰就睡），
而它在睡梦里念叨一句，正是「桌角有只小东西在活着」的那点动静 —— 梦话不摘打盹脸，
醒着才说实话（醒着才可能拉你玩一局）。想让它整天都醒着，改 `idle.ts` 的 `IDLE_AFTER_MS` 就行。

**闸门集中在 `presence.ts`**（三处共用，必须一致，不然就是一只忽冷忽热的宠物）：
形象显示着（收起来 = 别打扰我）、人在电脑前（`getSystemIdleTime() < 5 分钟`）、
不在专注与敲琴里、距它上一句话 ≥ 2 分钟；再叠加各自的冷却。

「你回来啦」看的是**离开的时长**：锁屏 / 合盖时记一笔时间，解锁 / 唤醒时算差值 ——
和 system-events 同一套判断，黑着屏的那一半不表演。离开不到 10 分钟不算「回来」，
顺手锁个屏不该被问候。

纪念日（「我们已经认识 100 天啦」）只在 7 / 30 / 100 / 200 / 365 … 这些日子说，
日期从 `pet-state.json` 读（与配置、对话历史放在同一目录；`PET_CONFIG` 指向不同位置的
「多宠」场景各带各的）。**这个功能是后加的，之前的历史无从得知** —— 所以第一天是从
「这次更新后第一次启动」算起的，不是编一个过去的日期。

### 双击气泡看全文

气泡只显示开头 60 字（说不完的部分在对话窗口里）。**内容被截断时**，双击气泡能把对话窗口调出来看全文。

两处细节值得记一笔：

- 气泡本身是 `pointer-events: none` —— 它一旦能收鼠标事件，命中判定和拖动就会把「鼠标在气泡上」
  当成「鼠标在形象上」。所以双击是用**坐标**判的，不给气泡挂监听。
- 只有**被截断**的气泡才算进「可交互区域」。否则形象头顶会凭空多出一片挡住桌面的地方，
  而那时双击本来也没有意义。实测的对照：形象上可交互、截断气泡上可交互、短气泡上照旧穿透。
- 点截断气泡**不会**逗到桌宠：`pointerUp` 里加了一道「不在形象上就不反应」的判 ——
  少了它，单击气泡会换一张脸，双击两次还会凑够「连点三次」把它惹毛，而用户只是想看全文。

> 形象上的双击入口（开气泡输入框）在 2026-09-20 就被去掉了，理由是「点形象本身就是逗它的动作、
> 连点两下很常见」。**这次加回来的是另一件事**：目标是气泡不是形象、动作是看全文不是抢键盘的输入框，
> 而且只在内容被截断时生效。

## 长期记忆

它有一份可以手改的长期记忆：`memory.md`，住在配置文件旁边（和 `chat-history.json` 同一个目录 ——
`PET_CONFIG` 指向不同位置时，多只宠物各记各的）。托盘「打开记忆文件…」直接打开它。

写入只有两条路，都可控：

| 来源 | 时机 | 花不花 token |
| --- | --- | --- |
| 你说「**记住：…**」 | 立刻落盘（同一句不会记两遍），**这一轮照常交给模型** | 一次普通对话 |
| **深夜日记** | 每天 23:30–23:59 之间挑一次，把「上次整理之后的新对话」摘要成 ≤5 条长期事实 | 一次小调用（低温度、≤400 token） |

「记住」为什么还走模型：回执要的是**它自己那句话**（拍板时明确选的「走一次模型」），
落盘是本地动作，两条互不等待 —— 而这一轮的系统提示里已经带上这条新记忆了，
它回「好，记下了」的时候是真的看得到。顺带跳过本地陪玩：「记住：我不喜欢猜数字」
里的「猜数字」不该真开一局。

日记只挑「以后相处还用得上」的：怎么称呼你、喜好与忌讳、重要的人和事、在做的事。
寒暄、天气、当次闲聊不记；已经记过的会在提示里列出来让它别重复。模型回「无」也算跑过
（进度照样前进，不重复花那次调用）；真失败了进度不动，第二天一起补 —— 只会晚一天，不会漏内容。
半夜机器睡着、应用没开也同理：跳过的那天由第二天覆盖。

记忆怎么用：**每轮对话随系统提示注入**（约几百 token 的常驻成本），并附一句
「相关时自然提起，不必逢事复述」。「选中即处理」的任务轮次**不注入** ——
翻译要的是干净指令，不是主人的私事。

删除：直接编辑文件（删行、全删都行），编辑即生效；没有「清空记忆」按钮，
托盘「打开记忆文件…」是唯一入口。托盘「清空对话历史」**不动它** —— 对话框里那句提示已注明。

上限 60 行，超了从最旧的开始丢（先写 `.tmp` 再 rename，和配置、对话历史同一套原子写）。

## 陪玩

它有些话能在**本地接住**：点单、帮你决定、三个小游戏。判定与状态都在主进程
（`main/play.ts`），一句话就能开局，不用点任何菜单：

| 你说 | 它做 |
| --- | --- |
| 「哭一个」「戴上墨镜」「喝奶茶」「喵」 | **表情点单**：当场换上那张脸，顺口回一句（会从当前形象真有的表情里挑） |
| 「帮我决定：吃面还是吃饭」「抛硬币」「摇骰子」 | **帮你决定**：选项给在触发词前或后都认；没给选项就教你怎么说 |
| 「猜数字」 | 1–100，它说「大了 / 小了」，猜中报次数 |
| 「猜拳」/「石头剪刀布」 | 你出石头、剪刀、布，它报自己出的和这局谁赢（连赢三局它会不服） |
| 「猜表情」 | 它挂一张脸让你猜（挂 10 分钟没人接就自己收掉），猜错两次说破答案 |
| 「好无聊」「玩什么」 | 报一遍它会玩什么 |

**为什么不走大模型**：① 判定必须**确定** —— 模型偶尔会把「大了」说成「小了」，
照着猜下去会疯；② 这些回答要**快**（本地是同步出的，气泡立刻就有）、要**免费**、
断网也能玩。表情清单也从当前形象的 `model3.json` 现读 —— 换个形象，点单不会指着一个不存在的脸。

**本地轮次不进上下文、也不落盘**（`ChatMessage.local` 这个标记）。这是刻意的：
让模型在下一轮读到「user: 石头」，它只会莫名其妙地接着猜拳。
但界面上照常显示 —— 回复走的是同一套对话事件，形象气泡与对话窗口都会画
（顺带修掉一处竞态：回复比 `sendChat` 的返回值先到，对话窗口据此不再留一个永远转圈的空气泡）。

两句护栏：

- **点单只认短句**（≤ 12 字）：长句里带个「哭」多半是在说心事，那该由模型去接。
  同理「难过」「委屈」刻意不做点单词 —— 那是想被安慰，不是想看点单。
- **游戏中途你换话题，这一局就安静结束**：不再追问「还没猜呢」，那句话照常交给模型。

**邀请是个承诺**：碎碎念发出的邀请（「要不要玩个猜数字？」）在 2 分钟内回一句「好」就真的开局
（回「不玩」也行）。所以只有「心里已经想好一个数」这类话才会用来邀请，而且只在它醒着的时候。
邀请与猜拳还会顺手把按钮挂到气泡上（见「气泡里的选项按钮」）：想玩哪个点哪个、出拳点一下就行，
打字那条路照常保留 —— 两条路走的是同一段代码，点出来的回合一样进对话窗口、一样带 `local` 标记。

「清空对话历史」会把进行中的那一局一起收掉（猜表情挂着的脸也摘掉）—— 它属于「这段对话」。

## 几个刻意的设计选择

**拖动为什么不用 `-webkit-app-region: drag`？**
它会吞掉元素上的鼠标事件，后续想加「点击形象触发对话」就做不了。改为主进程轮询鼠标位置移动窗口：
渲染层只报告按下/松开，位移超过 3px 才算拖拽，因此**点击与拖拽可以区分**。

也正因为判定权在主进程（它看得到真实光标），「拖动开始」这一刻要由它推回渲染层
（`pet:drag-moved`）—— 渲染层据此在拖动过程中就挂上 `晕晕`，而不是等松手才补一张晕脸。
这条事件只在位移刚过阈值时发一次。

**点击穿透为什么需要 `forward: true`？**
桌面宠物不该挡住桌面图标。鼠标不在形象上时窗口设为忽略鼠标事件，但必须带 `forward: true`，
否则穿透状态下收不到 `mousemove`，鼠标移回形象上时窗口就再也接管不回来了。

**为什么 Live2D 是动态 import？**
`pixi.js` + `pixi-live2d-display` 只在真的要跑 Live2D 时才加载；占位形象路径不背这个包体。
同时把对 Live2D 库的依赖收窄到结构化类型（我们真正调用的几个方法），库升级时不容易被类型变动卡住。

**为什么渲染层拿不到 AI 配置？**
`toRendererConfig()` 会剥掉整个 `ai` 段再下发。API Key 只存在于主进程内存里，不进渲染进程。

**对话状态为什么住在主进程？**
同一条理由还要再往前一步：API Key 与磁盘都只该主进程碰，所以会话（历史 + 正在生成的那一轮）
也放在同一侧 —— 渲染层能做的只是「发一句话」和「听增量」。何况渲染层本来就留不住状态：
形象渲染器会随「切换形象 / 重新加载形象」重建，对话窗口会关了再开，而对话必须接着进行。

**增量事件为什么推「到目前为止的完整文本」，而不是本次的片段？**
两个消费方（对话窗口的消息流、形象气泡）都只是把这块文本整体替换上去，不用各自维护累加状态；
漏收一次事件也不会把句子接错位，最坏只是慢一拍。窗口关掉再打开时还能从快照里拿到中间态接着画
（`ChatHistorySnapshot.streaming`），换成片段就得让每个消费方自己攒，还要处理「从第几段开始攒」。

**清空为什么要走广播？**
清空有两个入口（对话窗口的按钮、托盘菜单），可能发生在任一窗口开着的时候。
界面收尾统一挂在 `chat:cleared` 这一条广播上，而不是在每个入口各写一遍 ——
否则「从托盘清空时对话窗口还开着」这条路径就会留下满屏的旧消息。

**生产环境为什么不用 `loadFile()` 走 `file://`？**
Chromium 禁止在 `file://` 页面上用 `fetch`/XHR 读取本地文件，而桌宠必须能读 `model3.json` / `moc3` / 贴图。
踩过的坑是：**dev 模式一切正常，打包后却永远加载不出模型**。常规歪招是 `webSecurity: false` 或
`--allow-file-access-from-files`，两者都会把渲染进程的安全边界整个拆掉。这里改为注册 `app://`
自定义协议（`standard + secure + supportFetchAPI`），让本地资源以正常的 Web 语义被访问。

**CSP 为什么不能加 `unsafe-eval`？**
PixiJS 6 内部用 `new Function()` 生成 uniform 同步代码，会被 `script-src 'self'` 拦下并抛
`Current environment does not allow unsafe-eval`。官方为此提供了 `@pixi/unsafe-eval`：
用预生成的代码路径替换 eval。装这个包，而不是放宽 CSP。

> 这一轮顺带记一笔给下次写探针的人：Electron 33 **没有** `process.mainModule`，
> 在 inspector 里拿 `electron` 模块要用
> `process.getBuiltinModule('module').createRequire(process.execPath)('electron')`。
> 另外 `pbcopy` 在非 UTF-8 locale（`LC_CTYPE=C`）下会**吞掉非 ASCII 字节**，
> 中文剪贴板要用 `clipboard.writeText()` 从应用进程里写。
>
> 还有一条是这轮补的：读托盘菜单别用 `queryObjects(Menu.prototype)` —— 每次 `rebuildMenu()`
> 都会建一个新 Menu、旧的并不回收，`queryObjects` 抓到的数组里先读到的往往是**上一份**，
> 于是勾看起来是反的（这个坑上面记过，我这轮还是又踩了一次）。而 `Tray` **没有**
> `getContextMenu()`（Electron 33 的 typings 里只有 `setContextMenu`），拿不到「正在用的那一份」；
> 管用的办法是给 `Tray.prototype.setContextMenu` 挂个钩子，把每次设进来的菜单记到 `globalThis` 上，
> 之后读它拿到的就是最新的。顺带：已销毁的旧菜单 `menu.items` 是 `undefined` 而不是抛异常，
> 所以遍历时的守卫要写成 `Array.isArray(items)`，`try/catch` 挡不住它。
>
> 再补一条：模拟点一个 checkbox 菜单项时，**不要自己先翻 `item.checked`** —— Electron 给 MenuItem
> 的 `click` 包了一层，对 checkbox/radio 会先 `checked = !checked` 再调你写的处理器，你再翻一次
> 就是翻了两次 = 没翻。症状很阴：开关看起来「反着走」（点「关掉」实际写进去 `true`）。
> 直接 `item.click(item, null, {})` 就对了。
>
> 最后一条是环境坑：这台机器在电池上睡得很勤（`pmset -g log` 里一串 `Maintenance Sleep` / `DarkWake`），
> 进程被冻住之后探针里的 `setTimeout` 会被整段拉长 —— 一次 66 秒的等待实测跑了 **734 秒**，
> 看起来像「功能没生效」，其实只是机器睡了。跑长探针时用 `caffeinate -i node …` 把系统睡眠挡在门外
>（`-i` 只挡闲置睡眠，不会把屏幕点亮）。
>
> 这一轮（陪玩 / 闲聊）又添四条：
>
> 1. **探针实例的形象会被真实光标「抚摸」**。探针不注入鼠标事件，但窗口是真实桌面上的一个窗口 ——
>    鼠标扫过形象就按抚摸处理（挂上 `脸红` / `晕晕`），于是「这一轮只有这一张脸」这类断言会莫名其妙地失败。
>    开跑前把窗口挪到离光标最远的那只角（`screen.getCursorScreenPoint()` 判方向，`workArea` 里贴边放）。
> 2. **本地轮次的 `done` 先于 `sendChat` 的返回值**。本地回复是同步生成的，所以「返回值还没到、
>    对话事件已经到了」不再是小概率竞态而是常态 —— 探针里读回复要按「事件计数变化」读，不能读 `await` 的返回值；
>    生产侧那一半见修复记录里的空气泡。
> 3. **`Date.now` 打偏移只对用它算间隔的模块有效**（smalltalk 的下次搭话、play 的邀请有效期），
>    `new Date()` 不受影响（每日问候、饭点判定都是 `new Date()`）—— 想验饭点得连 `Date` 构造一起打；
>    这一轮没打，靠真实时间验的是启动问候。另外偏移**不会**让闲置时钟提前打盹：
>    它比的是 `Date.now() - lastActivityAt`，偏移对两边同时生效、差额不变 —— 要它立刻打盹就再往前推一次偏移；
>    反过来，验「醒着」的分支要周期性 `reportActivity()` 续命（它不改「上一次说话」，挡不住碎碎念）。
> 4. **`powerMonitor.getSystemIdleTime` 可以直接在 inspector 里打桩成 5 秒** —— 不然「人在电脑前」
>    这一条会随探针跑的人的走动随机失败。
>
> 这一轮（选项气泡 / 长期记忆）再添两条，第一条是这轮最贵的教训：
>
> 1. **跑探针时，屏幕上那只测试桌宠会被真人点。** 它是一只有窗口、会说话的桌宠，
>    按钮就摆在气泡底下 —— 我抓到过一次主进程日志里 17 条 `[ask] 选了「布」`，第一反应是
>    「代码在自问自答」，CDP 探针装上去才看清是 `isTrusted: true` 的真实 mousedown/mouseup（人在点）。
>    所以「谁在点按钮」这类断言，先看**探针记录里有没有非合成的点击**，再看代码。
>    对策：开跑前 `window.pet.hidePet()`（注意 `showPetWindow()` 会在每次本地回复时把它叫回来，
>    要连点几次才静得下来），或者在主进程 inspector 里把窗口挪出屏幕 / 置 `setOpacity(0)`；
>    顺手把主进程日志里多出来的 `[ask] 选了…` 当作「测试被污染」的信号。
> 2. **`require` 在 inspector 里不一定可用。** 同一个「挪窗口」脚本，第一次跑
>    `require('electron')` 成功、重启同一个进程后同样的写法报 `ReferenceError: require is not defined`
>    （评估所在的上下文不同）。要稳就用上面那条
>    `process.getBuiltinModule('module').createRequire(process.execPath)('electron')`。

**未能自动验证、需要你亲手确认的十三项**（都依赖真实系统光标、键盘焦点、原生菜单或真实的硬件事件，
注入的事件绕过了它们）：

- **拖着走的手感** —— 拖动这条链路本身已经用假光标实测过（见上表），剩下机器验证不了的只有
  「拿真实光标拖起来跟不跟手」：主进程按 16 ms 轮询，理论上最多落后一帧。
- **气泡淡出被悬停打断** —— 指针停在气泡上时那 8 秒的计时应当暂停、移开后再重新计时。
  合成事件的 `pointermove` 能让气泡进入悬停态，但移动不了真实光标，所以计时能不能被打断
  只能由人把鼠标停上去看一眼。
- **敲琴的键盘焦点** —— 按键本身是用 CDP 注入验证的（注入直接进页面，不看焦点），
  但「托盘开始之后形象窗口真的拿到了键盘焦点、按 A/S/D/W/1 有声音」要用真键盘试一次；
  同理「点到别的窗口后收不到键」这条也依赖真实焦点。
- **深夜打盹的 `阴暗` 分支** —— 闲置打盹本身是实测过的（切到 `闭眼口水`），但「23:00–6:00 之间
  换成 `阴暗`」这一支只在白天开发时读了几遍 `isNight()`，没有把系统时间调到深夜实跑过。
- **透明区域真的能点到桌面** —— 判定这一侧是实测的（轮廓外的点判「不命中」、主进程据此把窗口设成忽略
  鼠标事件），但「鼠标移到那一圈上时，点得到底下桌面上的图标」只有真实光标能试 —— 合成事件不走操作
  系统那层。挑个明显的空处试：窗口上部那 140 px（形象没画到的整条带），或者人物轮廓外的四角。
- **托盘里的「始终置顶 / 点击穿透」勾选** —— 开关的应用与写回走的是同一条 `patchConfig()`
  （拖动落点的写回 + 重启恢复已经实测，见上表），但原生菜单点不了，所以「点一下勾、重启后勾还在」
  要你亲手点两下：改一个 → 重启 → 看是不是还保持。
- **真鼠标双击截断气泡** —— 上面那条双击是用 CDP 合成事件测的，它**直接进渲染层**，绕过了
  「这个点到底穿不穿透」那一步（合成事件不看操作系统的忽略状态）。要确认的正是被绕过的那一环：
  拿真鼠标移到一段被截断的气泡上（此时窗口应停止穿透）→ 双击 → 对话窗口带着全文出现。
  顺带确认短气泡上没有这个效果（双击无反应，且那一片照旧穿透）。
- **久坐提醒（连续在场 90 分钟）** —— 判定依赖的 `powerMonitor.getSystemIdleTime()` 实测可用，
  但「真的坐满 90 分钟然后说一句话」没法在开发时压缩：阈值是模块常量不是配置项。
  想早点看到效果，可以临时把 `companion.ts` 的 `SEDENTARY_AFTER_MS` 改小再跑。
- **深夜问候（23:30 之后第一次活动）** —— 与上一条同理，需要一个在深夜窗口里的时钟。
  `isLateNight()` / `nightKey()`（跨午夜不重复问候）都只做了代码审查，没在深夜实跑过。
- **真的拔一次电源线、真的断一次网** —— 系统事件这两条链路里，「收到事件之后做什么」是探针实测的
  （`powerMonitor.emit('on-battery')` 走的是真处理器、真 IPC、真气泡与真表情；断网那一路把
  `net.isOnline` 打桩成离线，跑完了 30 秒判定与「恢复在线再说一遍」的往返）。没验的是**最前面那一环**：
  macOS 会不会因为这个动作真的发出这个事件（探针发的是合成事件）。拔掉充电器看它有没有说
  「诶，线掉了？」、插回去有没有「充上啦」；顺手关掉 Wi-Fi 一分钟，看 30 秒后有没有「网没了」——
  后半段顺带验的是 `net.isOnline()` 在真离线时确实返回 `false`（打桩验不了这一条）。
- **真的用双指轻点在形象上轻点一下** —— 「收到右键之后收起」整条链路是注入真鼠标事件实测的
  （见上表），没验的是**你这台机器的触控板手势到底会不会发出那个右键事件**：它取决于
  「系统设置 → 触控板 → 辅助点按」选的是「用双指轻点」还是别的（角落点按之类）。
  用真的双指轻点戳一下形象，看它有没有收起来；顺手试一下鼠标右键与 `⌃`+点按（它们是同一个事件，
  应当一起生效），再确认托盘的「显示 / 隐藏」能把它叫回来。
- **碎碎念的节奏与体感（这一轮加的）** —— 探针把时钟拨快，验的是「到点会说、说什么、
  什么情况下不说」；验不了的是**一天下来烦不烦**。30–60 分钟、睡前那句 45 分钟冷却、
  打盹 5 分钟，这几个数都是拍的。用一两天再看：嫌吵就托盘点掉「闲聊」
  （陪玩不受它影响），或者改 `smalltalk.ts` 顶上的常量。
- **用真鼠标点一次气泡上的选项按钮（这一轮加的）** —— 这条其实被**意外**验掉了一半：
  测试实例摆在桌面上时被真人点过（见上面探针笔记里那 17 条 `选了「布」`，探针确认是
  `isTrusted: true` 的真鼠标事件），说明真光标确实能点中按钮、且那一刻窗口没有在穿透。
  还留着要目视确认的两点：真光标**悬停**在按钮上时那一小块不再点得到桌面（穿透退让的手感）、
  以及此时**双击气泡不再开对话窗口**（该让位给按钮）。顺手试一次就行。

## 修复记录

上面这些能力第一次做完后做过一轮逐文件排查，之后每一轮改动里抓到的问题也一并记在这里，避免以后重新踩：

**选项气泡：按钮必须在「那句话说完」之后挂（这一轮）**
按钮是挂在气泡**当前内容**上的（内容一换就自动撤，见 `pet/bubble.ts` 的 `setText`）——
所以挂按钮的时机只能在回复的 `done` 事件之后。第一版把 `askRpsTurn()` 放在 `stepRps()` 里（即回复还没送出去时），
结果按钮刚挂上就被紧跟着落下来的那句话当成「旧内容」撤掉，猜拳永远看不到按钮。
修法：回合的出口统一走 `session.replyLocally()`，它发完 `onDone` 再调 `play.afterLocalReply()` 补挂。

**猜拳的三处 `game = null` 收敛回 `endGame()`（这一轮）**
「这一局结束」有好几个入口，之前有三条路直接写 `game = null`，绕过了 `endGame()` 的收尾
（摘脸、停闹钟）。这轮按钮要在局结束的一刻撤下来，正好需要一个统一的收尾点 —— 顺手把三处都收进
`endGame()`，它现在做四件事：摘脸、停闹钟、清状态、撤按钮。老注释里那次「某条路漏掉 `game = null`、
一局阴魂不散」的教训，从「记得写」变成了「没法漏」。

**清空对话的文案（这一轮）**
加长期记忆之后，托盘「清空对话历史…」那句「桌宠会忘掉之前聊过的内容」变成半句谎话 ——
记忆在另一个文件里、不在被清之列。提示语改成「长期记忆不在被清之列（要删请编辑记忆文件）」，
免得用户以为清一下就忘干净了。

**测试时被「真人点击」骗过一轮（这一轮，教训）**
见上面探针笔记里的 17 条 `选了「布」`：第一反应是代码在自问自答，装了 CDP 探针（拦
`HTMLElement.prototype.click` + 捕获阶段 click/mousedown）才看清是真实鼠标事件。
以后遇到「没人操作却发生交互」的断言失败，先分辨事件是不是 `isTrusted`。

**Live2D 缩放自我反馈（影响最大）**
`refit()` 用 `model.width` 当「原始尺寸」，但 Pixi 的 `model.width` 是**已缩放**尺寸
（`scale.x * 本地包围盒宽度`）。于是第二次 refit 把自己上一次的结果当输入，缩放被反复重算，
最终停在 `modelScale` 上而不是铺满窗口 —— 2400×4500 的 Haru 被按 1:1 塞进 320×460 的窗口，
看到的是模型肚子的一块放大图；`modelScale` 配置完全失效；命中框被算到窗口上方（y 为负），
点击穿透永远判定为「不在形象上」，**形象既点不动也拖不动**。
而 refit 必然被调用多次（`ResizeObserver` 注册后立刻回调一次），所以这不是理论风险。
修法：量原始尺寸前先把 scale 归 1，结果缓存下来，refit 变成幂等操作。

**重建形象泄漏 WebGL 上下文**
一次「重新加载形象」主进程发了 `configChanged` + `modelReloaded` 两条消息，渲染层两个订阅都重建形象。
两次异步挂载互相覆盖，先完成的那个渲染器既没进 `current` 也没被销毁 —— canvas 留在 DOM 里、
Pixi ticker 继续跑。实测一次点击后 `mountCount` 从 1 变 3、DOM 里有 2 个 canvas。
修法：主进程只发一条 `configChanged`；渲染层再加一道挂载代号（generation）兜底，
过期的那次自己 `destroy()`。

**AI 人设配置从未生效**
`ai.systemPrompt` 在配置里定义、在 `ai:ping` 脚本里用了，但应用内的对话链路从头到尾没人读它 ——
用户在配置里写的人设被静默忽略。修法：在 IPC 里用 `withSystemPrompt()` 注入，
并剔除渲染层传来的 system 消息（人设由用户的配置文件决定）。

**Cubism Core 的失败结果被永久缓存**
`loadCubismCore()` 把 promise 缓存了起来，失败也缓存。于是「没装 Core → 看到提示 → 跑 setup:live2d →
点重新加载」这条最自然的路径永远走不通，只能重启应用。另外 404 属于 Chromium 会启发式缓存的响应，
重试还得绕开缓存。修法：失败不缓存 + 重试带变化的 query + 失败时摘掉死 script 节点。

**切换形象时贴图只增不减（这轮抓到的）**
`pixi-live2d-display` 的 `model.destroy()` 默认**不碰贴图**，而 PixiJS 的贴图是按 URL 存在
全局 `TextureCache` 里的。于是每切换到一个新形象就把它的贴图永久留在缓存里：实测把 6 个形象
都看过一遍后，缓存里攒了全部 29 张贴图（约 490 MB 解码数据），而且永远不会释放。

修法是给 `destroy()` 传 `{ texture: true, baseTexture: true }`。这两个标志缺一不可 ——
Pixi 的 `Texture.destroy(true)` 内部会先 `removeFromCache` 再销毁 baseTexture；
只销毁不清缓存键的话，下次切回这个形象会拿到一张已经销毁的贴图，直接渲染成空白。
修复后实测缓存数严格等于当前形象的贴图张数（5 / 14 / 3 / 1 / 5），切回后渲染正常。

**库的 `resetExpression()` 不更新自己的记账（这轮抓到的）**
`pixi-live2d-display` 的 `ExpressionManager.resetExpression()` 只把画面切回默认，**没有更新
`currentExpression`**。而 `setExpression()` 开头有一句「要设的正是当前表情就直接返回 false」：

```js
if (index === this.expressions.indexOf(this.currentExpression)) return false;
```

两件事凑在一起：点「还原默认」之后再点回刚才那个表情，会被判定为「已经是当前表情」，
直接返回 false 什么都不做 —— 表现为**点了没反应**，而且是「还原之后想再套回去」这条最自然的操作。
修法是在 `resetExpression()` 之后把 `currentExpression` 归位到 `defaultExpression`
（两个都是库类型声明里的 public 字段）。这是绕开库的实现疏漏，不是我们自己的状态。

**「名字不存在」和「已经是当前表情」都返回 false**
同一个 `setExpression()`，名字查不到（`getExpressionIndex` 返回 -1）也返回 false。
只看返回值根本分不清这两种情况，于是「你已经套着这个表情了」会被误报成「这个表情不存在」。
修法是先自己查一次表（`getExpressionIndex(name) < 0`）再动手，两种情况的提示才准确。

**形象清单扫错了目录（dev 专属）**
`modelsRoot()` 一开始固定按 `__dirname/../renderer/models` 找模型，但 dev 模式下渲染层由
Vite dev server 提供、模型来自 `src/renderer/public/models`，`out/renderer/models` 只是上一次
build 的残影。症状是：新加的模型渲染层明明加载得出来，托盘菜单里却看不见。
改为按 `ELECTRON_RENDERER_URL` 是否存在来区分两种运行方式。

**鼠标跟随从来没生效过（只留 Q版 A 那轮抓到的）**
配置里 `model.autoInteract` 一直开着，文档也把它写成「让模型自动跟随鼠标」，但它是**死配置**：
库把鼠标跟随挂在 Pixi 的 InteractionManager 上，而那个管理器监听的是 **canvas 的 DOM 事件**，
`style.css` 里为了让命中判定统一走 hitBox 逻辑，给 canvas 设了 `pointer-events: none` ——
事件永远不会以 canvas 为目标，这条链从头到尾收不到东西。

实测确认：在窗口里移动指针，`pointermove` 的 `event.target` 一直是 `pet-root`，从来不是 `CANVAS`。
修法不是在 canvas 上放开 `pointer-events`（那会把点击穿透与拖动两套逻辑一起牵扯进来），
而是在渲染层已有的窗口级 `pointermove` 上直接驱动 `model.focus()`（新增 `pet/lookAt.ts`），
并把传给库的 `autoInteract` 显式关掉 —— 顺便省掉 InteractionManager 每次指针移动对舞台做的命中检测。
指针离开窗口时把目光收回正中，否则它会一直盯着最后停下的那个角落。

> 验证这条踩了一个坑值得记下来：`Cubism4InternalModel.update()` 结尾会调 `model.loadParameters()`
> 把参数数组**倒回**动作开始前的状态，所以帧与帧之间 `getParameterValueById` 读到的一律是基础值，
> 跟 focus 毫无关系 —— 想证明「眼睛动了」只能比像素。最后是把 Ticker 停掉、用固定 dt 序列推进
> 同样多帧再逐像素比：指针换边后 11% 的像素发生变化，差异区域正好落在头/上半身。

**常驻程序稳定烧掉 27% 的 CPU（只留 Q版 A 那轮抓到的）**
起因是查别的 bug 时顺手 `top` 了一下，发现它一直在用四分之一个核。原因是
`pixi-live2d-display` 把模型的 `deltaTime` 累加挂在 `Ticker.shared` 上，而 Pixi 的 `Application`
默认会**自己新建一个 Ticker** —— 等于每帧跑两个 rAF 循环，而且限帧得设两处才管用。

修法是 `new PIXI.Application({ sharedTicker: true })` 让两者共用一个 Ticker：**27% → 24%**。

> **这里记一次错误的取舍，免得以后再犯。** 当时顺着「桌宠是常驻程序，30 fps 肉眼分不出来」
> 的思路，又把 `Ticker.shared.maxFPS` 钉在了 30，实测降到 17%，看起来是个漂亮的胜利。
> 结果是用户直接反馈「帧数低的离谱，卡卡的」—— 省电不能拿流畅度去换，尤其是**在没人要求省电的时候**。
> 已改回不限帧。
>
> 顺便把「还有没有别的杠杆」一次性测清楚了，省得下次再猜：
> - **分辨率没用**：resolution 2 / 1.5 / 1 → 24.4% / 24.3% / 24.8%
> - **抗锯齿没用**：`antialias: false` → 25.3%（比开着还高一点，噪声内）
> - **画布面积没用**：窗口 320×460 → 320×340，测不出差别
> - **限帧有副作用**：60 Hz 面板上 `maxFPS = 60` 只有 58.3 fps，`59` 只有 56.3 fps ——
>   它是「这一帧不够时间就跳过」的闸门，只有恰好等于刷新率时才不丢帧，所以最终选择不限帧。
>
> 结论：那 3.5 ms/帧的开销全在 Cubism 的骨骼/物理/网格更新里，除了降帧率没有别的杠杆。
> 真正能省的是**把形象隐藏起来**（托盘「显示 / 隐藏」）—— 实测隐藏后渲染进程直接掉到 **0.0%**，
> 因为 Chromium 在窗口不可见时会停掉 rAF。

> 顺带一个测量教训：`Ticker.FPS` 不能用来量真实帧率。Pixi 在 maxFPS 闸门**之前**就更新了
> `elapsedMS`，被跳过的帧同样把它写成 ~16.7 ms，于是读数在 30/60 之间乱跳。
> 只能给 `internalModel.update` 打桩计数（而且打桩必须幂等：重复包装一次，30 fps 会被数成 59 fps）。

**库的眨眼在这个模型上等于不存在（眨眼这轮抓到的）**
`model3.json` 补过 `Groups.EyeBlink`、库里 `CubismEyeBlink` 也照常建了，所以「会眨眼」
看起来已经有人管。实测 75 秒：一次都没眨。原因有两层 ——

一是**时钟被饿死**：`Cubism4InternalModel.update()` 只在 `!motionUpdated`（本帧没有任何
动作在播）时才调 `eyeBlink.updateParameters()`，而待机动作 4 秒一轮、播完立刻重启，
每轮只漏得出 1 帧空档。75 秒 4500 帧里只有 **19 帧**（0.4%）喂到了眨眼时钟，总共才攒下
0.382 秒 —— 流速只有真实时间的约 1/200。

二是**抽签的间隔太远**：阈值是 `userTimeSeconds + random() × (2 × interval − 1)`
（interval 默认 4 秒，即每次重新抽 0–7 秒的内部时钟）。按上面这个流速换算回真实时间，
**平均要等约 11 分钟**，最远二十多分钟（那轮抽到的阈值是 1.16 秒，折合也要约 4 分钟）。
就算偶尔眨上了，三相时长（0.1 / 0.05 / 0.15 秒）也是库写死的常量，
表达不了「每 4–8 秒」这种需求。

修法是不再用库的眨眼：自己写 `pet/blink.ts`（纯调度、零依赖），在 `beforeModelUpdate`
时刻把 `Groups.EyeBlink` 里的参数乘上开合度。三个实现细节都不是随便选的：

- **为什么挂在 `beforeModelUpdate`**：`update()` 结尾的 `loadParameters()` 会把参数倒回
  动作求值前的状态，所以「只作用于本帧」的写入必须发生在所有参数写入者（动作 / 表情 /
  呼吸 / 物理 / 目光）之后、`model.update()` 求值之前 —— `beforeModelUpdate` 正是这条线前
  的最后一个写入时机（库自己的眨眼也写在同一窗口里，只是不经过事件）。写在这里的值同样
  会被帧尾回滚，所以不需要任何事后清理。
- **为什么用乘法而不是绝对写入**：基准值不保证「1 = 睁开」—— `墨镜` 表情会把眼睛压到
  闭合，绝对写入等于把闭着的眼睛拉开。乘法只做一件事：睁着的眼睛闭下来，闭着的保持闭着。
- **参数 ID 从 `settings.getEyeBlinkParameters()` 取**：没登记 EyeBlink 组的模型本来就
  不会眨眼，与库的行为保持一致（当前形象是 `ParamEyeLOpen` / `ParamEyeROpen`）。

顺手把 `internalModel.eyeBlink` 置成 `undefined`：留着它，那个平均十一分钟一次的幽灵眨眼
仍会在某天突然闪一下。

**默认形象指向一个不存在的模型**
`DEFAULT_CONFIG.model.path` 还停在 `blue-cat/Blue cat.model3.json`，而 blue-cat 已经从仓库里去掉了。
新装的用户（或删掉配置文件的用户）会直接落到「模型文件不存在」的降级路径上。
已改成 `qpet-a/A_Qpet_90.model3.json`，同时配置文件模板里的示例改成从 `DEFAULT_CONFIG` 取，
不再手写一遍 —— 手写的那份就是这么过期的（`_readme` 里还留着 milestone 1 时代的 `sample/sample.model3.json`）。

**「重新加载形象」之后表情勾会撒谎**
重建渲染器会把表情清回默认，而主进程里那个「上次点了哪个表情」的变量不知道，
于是菜单里的勾会停在旧值上。修法是重载时一起清掉，顺便重建菜单（这样改了 `pet-model.json`
里的显示名也能立刻看到）。
这一条后来被更彻底地修掉了：表情做成可叠加之后，「上次点了哪个」压根表达不了当前状态
（可能同时挂着三个），于是改成**渲染层上报真实状态**、主进程只做缓存与画勾。
那个变量连同「radio 单选语义」一起下线了，顺带把「点了没反应时勾已经打上」的失配窗口也关掉了。

**连点 3 次不生效：最小间隔把计数一起吞了（做表情触发时自测抓到）**
`pointerUp` 里原本是 `if (now - lastTapAt < 180) return`，本意只是「别让脸在两帧内翻两次」，
但它把后面的连点计数也一起挡在门外 —— 而快速连点恰恰就是 `连点` 的定义，真实用户的点击间隔
经常在 100 ms 量级。表现是：无论点多快都只会随机换脸，`生气` 永远不出现。
修法是把「太快了」降级成只压掉换脸、计数照记。

**HTTP 失败没有脸（自测抓到）**
`流汗` 只挂在「网络层抛异常」那条分支上，而假端点回 401 走的是「返回了一个 `ok: false` 的结果」
那条分支 —— 结果是没配 Key、Key 写错、上游 500 这些**最常见**的失败全都不变脸。
两条分支是同一个「这一轮失败了」的两个出口，脸得是同一张。

**抚摸一碰就触发（自测抓到）**
方向反转计数把**第一笔**也算了一次（`lastDir` 从 0 起跳，第一笔必然算反转），
于是指针从形象边缘移到身上、再抖两下就凑够 3 次，`脸红` 会在用户只是路过时冒出来；
而且按住拖动时的一串 `pointermove` 同样计入，拖完松手可能连着冒两张脸。
修法是第一笔只定方向不计数、带按键的 move 直接不看。

**表情换成自建分层之后，那条 `resetExpression` 的绕坑代码一起下线了**
之前为了绕开库 `resetExpression()` 不更新 `currentExpression` 的疏漏，代码里手写了一句
`manager.currentExpression = manager.defaultExpression`。改成自读 exp3、自写参数之后，
库的表情槽整个不再使用，那段绕坑连同 `expressionManager` 的整套结构性类型一起删掉了。
教训记在这里：**绕坑代码要跟着依赖一起走**，不然下次读代码的人会以为那个坑还在。

**其余小问题**
- 窗口被关掉后（默认菜单的 Cmd+W）托盘「显示 / 隐藏」变成点了没反应的死按钮 → 改为自动重建窗口。
- 拖动过程中光标跑出命中框会切进点击穿透，鼠标松开的事件可能收不到、拖拽卡死 → 按住期间强制保持可交互。
- `app://` 协议遇到畸形百分号转义时 `decodeURIComponent` 抛异常，handler 直接 reject → 改为返回 400。
- 请求超时的文案只会说「超时（默认 ms）」，不显示真实毫秒数 → 传实际生效的超时值。
- 渲染层传来的 `temperature` / `maxTokens` / `timeoutMs` 没做范围校验，且 `NaN` 会漏过 `typeof` 检查 → 与配置文件同一套上下限夹取。
- 两条从不发送的 IPC 通道（`modelReloaded` / `requestReloadModel`）连同渲染层的订阅一起删掉了：
  形象重建早就统一走 `configChanged`，留着只是让「改哪里才会重建」变得难查。
- `pet-model.json` 的坏数据、模型目录里读不动的目录都会被跳过而不是抛出 —— 托盘是唯一入口，菜单构建失败等于应用没法操作。

### 逐像素命中判定（这一轮加的）

老语义是「包围盒内缩 15%」，于是形象轮廓之外那一大圈透明区域照样挡住桌面（这个 4068² 的正方形模型
尤其明显）。现在每两秒把模型离屏画一遍、缩成 64 格宽的 alpha 网格，判定时把点按比例映射回格子查邻域。

**离屏那条路有两个坑，都踩到了：**

1. **`extract.canvas(model)` 会按模型的本地尺寸开画面**（这个形象是 4068²）：一次 GPU 回读几十 MB，
   为了判一个点代价荒谬。自己给 `resolution`（`MASK_COLS / local.width`）把它压到 64 格宽，回读只有几 KB。
2. **`generateTexture` 带着 `skipUpdateTransform: true` 渲染**，会把模型在窗口里的**位置和缩放**一起画进那张
   小画面 —— 人物被缩成一个点。实测：那条路的掩码只有 **0.2%** 的格子有东西，而真实画面是 **38.5%**。
   修法是画之前把模型自身变换（位置 / 缩放 / 旋转 / 斜切 / pivot —— `anchor` 就是 pivot）临时归零，
   再用 `skipUpdateTransform: false` 强制重算世界矩阵，画完立刻还原。

**验证方式是把掩码和真实画面对账**（而不是「看起来差不多」）：截图（透明底）按同一网格统计每格里有没有
画到东西，与掩码逐格比 —— 一致率 **99.3%**、IoU **0.98**，抽查具体点也一致（(160,300) 两边都是 255、
(160,440) 两边都是 0）。模块自身走的是掩码那条路也确认过：包围盒内缩范围里的透明点 `(53,193)` 判「不命中」、
身上的 `(123,408)` 判「命中」，在那上面点一下仍然会触发表情。

**掩码拿不到时退回包围盒语义**（刚挂载的头几帧、或回读失败）：判错的代价是形象点不动、拖不动，
比多挡一点鼠标严重得多。

**顺带修掉一个和它相关的老 bug**：渲染层以前按「点击穿透开关」的值决定要不要上报「指针在不在形象上」，
而那个开关归主进程管 —— 用户在托盘里重新打开穿透之后，渲染层就不再上报，窗口会一直保持可交互
（要等下次换形象重下配置才恢复）。现在渲染层只如实上报位置，「要不要穿透」全归主进程判。

### 托盘的窗口开关与拖动落点写回配置（这一轮加的）

「始终置顶 / 点击穿透」以前只当次生效，重启回到配置文件的值；窗口位置更是每次都由系统重新摆。
现在两者都写回配置 —— 和「切换形象」共用同一个 `patchConfig()`：只动点名的那一节、原子写、
其余字段（`_readme`、用户自定义字段）原样保留。

**记下的坐标必须先验证再用**：那块屏可能已经拔掉了，照搬会让整窗落在屏幕外，用户既看不见也拖不回来，
只能去删配置文件。所以启动时要求窗口至少有 48×48 px 落在某块屏的工作区里，否则打一行警告交给系统摆。

### 其余小问题（这一轮）

- **表达式有异步竞态**：exp3 是异步取的，`play()` 在加载期间被 `remove()` / `clearAll()` 取消时，
  加载完还会把那一层插回去 —— 表现为「已经摘掉的表情又冒出来」（闲置醒来摘打盹脸时最容易撞上）。
  现在按名字记一个令牌，摘掉 / 清空会作废在途的那一次。
- **空回复不再写进会话历史**：模型偶尔吐一个空串，留着它会作为一条空的 assistant 消息发给模型。
- **配置文件改成原子写**（先写 `.tmp` 再 rename），与对话历史一致：这个文件写坏会连带丢掉用户的
  `_readme` 与自定义字段。
- **三条渲染层从不发送的 IPC 通道删掉了**（`pet:quit` / `chat:toggle-window` / `bubble:toggle`），
  `PetRenderer.playMotion` 同理：托盘直接调主进程函数，留着只会让「改哪里才生效」变得难查。
- **`bubble.html` 补上了 CSP**：三个渲染入口里只有它没有。安全边界不该因为「这个页面只有一个输入框」
  就放宽，而且补的当天就验证了没拦住自己的脚本与样式。
- **错误提示先说人话**：401 →「API Key 不对或没配」、404 →「接口地址不对」、429 →「请求太频繁或额度用完了」、
  5xx →「上游服务出错」，后面用 `·` 接上厂商原文（排查信息不丢）。气泡只显示前 60 个字符，
  所以人话必须在前面。


### 小助手：实现时踩到的几个坑（这一轮加的）

- **读剪贴板不能用轮询缓存。** 轮询是 1 秒一次，而「复制 → 立刻按快捷键」完全可能落在两次轮询之间，
  读缓存就会拿到**上一次**的内容 —— 那是个会让人莫名其妙翻译错东西的 bug。所以入口处
  `readClipboardText()` 是当场直读，`recent` 缓存只服务于「剪贴板历史」那份列表。
- **`ephemeral` 的过滤必须放在 `saveHistory()` 里，不能放在调用点。** 那个函数有六处调用
  （成功、失败、被停止、清空…），任何一处漏掉都会把剪贴板内容写进磁盘。放在 store 里意味着
  这个动作「没法被忘掉」，代价是 `saveHistory` 的输入与落盘结果不再一一对应 —— 注释里写明了。
- **喂给模型前要摘掉 `ephemeral`。** 它是我们自己的落盘标记，不该出现在请求体里。顺带把消息对象
  收敛成只有 `role` 与 `content` 的形状，跟 API 契约一致。
- **气泡可交互了，点击就会顺手逗到桌宠。** `pointerUp()` 原本不判位置（任何落到窗口的点击都算
  「点了它」）。把截断气泡纳入可交互区域之后，单击气泡会换一张脸、双击两次还会凑够「连点三次」
  让它 `生气` —— 而用户只是想看全文。修法是给 `pointerUp` 加上松手坐标，不在形象上就不反应；
  坐标由拖动层从 `pointerup` 事件里带出来（顺手让这条链路补齐了它一直缺的位置信息）。
- **专注与闲置的耦合做成了单向的。** 直觉写法是让 `idle.ts` 去问「在专注吗」，但那样两个模块会
  互相 import（focus 要 idle 的 `noteActivity` 来唤醒）。改成 focus 每分钟续一次 `noteActivity`：
  依赖只剩 focus → idle 一个方向，而且「专注期间不打盹」的语义正好就是「持续报告有人在场」。
- **托盘菜单会累积旧实例。** `rebuildMenu()` 每次都 `Menu.buildFromTemplate` 一个新对象，
  旧的并不回收 —— 用 `queryObjects` 做探针时会先读到**旧**菜单，一度让人以为「专注中」没生效。
  读托盘状态要以最新那个实例为准。
- **测试用的中文剪贴板踩了两个环境坑。** ① `pbcopy` 在 `LC_CTYPE=C` 的 locale 下会吞掉非 ASCII
  字节（写进去、读出来是空的），得从应用进程里用 `clipboard.writeText()` 写；② Electron 33 没有
  `process.mainModule`，inspector 里取 `electron` 模块要用
  `process.getBuiltinModule('module').createRequire(process.execPath)('electron')`。
- **给 `runTurn` 加参数时差点把聊天整个弄哑。** 新参数一开始叫 `turn`，而模块级的轮次计数器
  正好就叫 `let turn = 0` —— 参数把它遮住之后，`myTurn !== turn` 变成拿数字比对象、永远成立，
  于是**每一轮回复都会在生成完之后被当成过期丢掉**（模型白调、界面什么都没有）。
  `tsc` 的 `TS2367: This comparison appears to be unintentional` 逮住了它。
  这类遮蔽不会报错、只会静静地改语义，所以那个参数现在叫 `ctx`，并在签名里留了注释。

### 气头上再点（这一轮修的）

- **第四下点击会把「生气」盖掉。** `pointerUp` 里连点攒够 3 次就 `play('生气')`，但计数当场清零，
  于是第 4 下又从「反应池随机」那条路走出去 —— 表现是刚连点出气，再多点一下立刻被一张新脸替换，
  像那三下白点了。修法是在进池子之前加一道判：`生气` 还挂着就只把它续上（重新计 1.6 秒）。
  判定问的是渲染器（`activeExpressions()`）而不是交互层自己记一笔「我点出过生气」：
  生气的来路有三个（连点、托盘钉住、聊天关键词），只有表情调度器知道此刻到底谁挂着。
- **这条修复牵出一个老毛病：钉住的层会被一次交互续成限时。** 托盘的「试个表情」把表情钉成常驻，
  而交互（点一下、拖着走两步）会顺手重套同一个名字 —— 同名合并本来就是「刷新时长」，
  于是钉住的那张脸会在一次点击之后自己掉下来：用户刚做的「钉住」被一次无关的交互悄悄取消了。
  现在 `insert()` 里同名的旧层若是常驻，就不接受新的限时（反方向照常：常驻能覆盖限时，
  托盘一勾就能把正在闪现的表情定住）。

### 气泡把整句话吞成了一个省略号（这一轮修的）

- **`settle()` / `fail()` 里两个调用的顺序反了。** `begin()` 是「气泡起头」，里面有一句
  `textEl.textContent = '…'`（流式开始时先给个占位）；而 `show()` 是**先** `setText(text)`、
  **再** `begin()`。于是气泡处于隐藏状态时来一句现成台词：文本先写进 DOM、紧接着被占位符擦掉，
  气泡定格在「…」上 8 秒然后淡出。**番茄钟到点、久坐提醒、深夜问候、「剪贴板里没有文字」
  这些提示全都没显示过内容** —— 话说了，但只显示一个省略号。
- 能藏这么久是因为流式对话（`update()`）的顺序本来就是对的（先 `begin()` 再 `setText()`），
  而之前几轮的验证都走在流式那条链路上。这轮做系统事件时探针要求「气泡里出现那句话**本身**」
  （而不是「文本非空」），才把它照出来。修法：`show()` 里把 `begin()` 提到 `setText()` 之前，
  并在注释里写死这个顺序的原因。

**猜表情那一局阴魂不散（这一轮修的，探针抓到的）**
`finishFace()` 只做了两件事：摘掉挂着的那张脸、停掉收摊闹钟 —— **没有清 `game`**。
于是「猜对」与「猜错两次」这两条路走完之后，`game` 还指着那张已经摘掉的脸：
之后你说的每一句话都被当成猜错，一直重复「不对啦，这是……」（探针里 `抛硬币`、`好无聊`
连吃三记，看起来像这几条功能一起坏了）。修法：把清状态收进 `endGame()`，
让「结束」的所有入口（不玩了、猜对、猜错两次、超时、清空对话）都只走这一个函数 ——
少写一行 `game = null` 的代价已经演示过一次了。

顺带填掉同一处露出来的另一个坑：**挂着脸的时候，别的意图要先接住**。
原来的顺序是「猜不对就算猜错」，于是「抛硬币」这种短句会被算成猜错一次，
而用户其实已经换了话题；现在先判答案、再试点单 / 帮你决定 / 换一局，都没有才计入猜错
（判对仍排在判错之前：猜「猫猫」既像答案「猫猫贴纸」也像点单，那种时候当然算猜对）。

## 故障排查

**`npm install` 报 `EPERM ... ~/.npm/_cacache`**
npm 会把它误报成「缓存目录里有 root 属主文件」。真实原因通常是当前环境不允许写 `~/.npm`
（沙箱、权限收紧）。把缓存指到可写位置即可：

```bash
npm install --cache "$PWD/.npm-cache"
```

**Electron 二进制下载极慢或卡住**
默认从 GitHub Releases 拉取，国内常见只有 ~100 KB/s。用环境变量带镜像
（下载后仍会用官方 `checksums.json` 校验完整性）：

```bash
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```

这条**故意没有写进 `.npmrc`**：`electron_mirror` 是 `@electron/get` 读的键、不是 npm 的配置项，
npm 11 会把任何不认识的键当成 `Unknown project config` 报警，于是每条 npm 命令都要刷两行黄字。
放进 `.npmrc` 换来的是永久噪音，放在命令里只在需要时出现一次。

## 依赖与安全

`npm audit` 会报 7 个漏洞（2 moderate / 3 high / 2 critical），但**这些代码一个都不会进到应用里**：

- `.app` 里没有 `node_modules` —— 打包时只装 `out/`、`resources/`、`package.json`。
  实测 `Contents/Resources/app/` 下确实只有这三样。
- 7 个漏洞全部来自开发期依赖：`gh-pages`（`pixi-live2d-display` 误当运行时依赖的**发布工具**，
  我们从不调用）和 `extract-zip`（`@electron/get` 解压 Electron 压缩包用，装包时一次性）。
- 所以 `npm audit --omit=dev` 是 **0 vulnerabilities**。

`pixi.js` / `pixi-live2d-display` / `@pixi/unsafe-eval` 放在 `devDependencies` 而不是
`dependencies` 里，也是同一个道理：它们是渲染层的源码依赖，但**已经被 Vite 打进 renderer 的
chunk**（产物里能看到 `pixi-*.js`、`cubism4.es-*.js`），运行时不需要从 `node_modules` 解析。
放进 `dependencies` 会让 electron-builder 以为要把它们拷进包里。

## 已知限制

- 窗口尺寸改动需要重启才能生效（透明窗重建成本高，暂未做热应用）。
- 帧率**不设上限**，跟着显示器刷新率走（`Live2DRenderer.ts` 里的 `TARGET_FPS = 0`；
  60 Hz 面板上就是 60 fps）。为什么刻意不写 60、以及 30 fps 那次错误取舍的完整记录，
  见上面的修复记录。可见时稳定占一个核的 24%，隐藏后是 0.0%。
  （模型是**一直在动**的：呼吸 `CubismBreath` 由库逐帧驱动，眨眼由自家调度器每 4–8 秒
  触发一次，所以「这一帧画面没变就跳过」这类优化根本用不上。）
- 点击穿透的命中判定用的是 **alpha 掩码**（把模型离屏画一遍缩成 64 格宽的小网格，每两秒刷新一次），
  形象轮廓之外的透明区域不再挡鼠标。两处仍然近似：掩码是**快照**（最长 2 秒前的那一帧，轮廓变化很慢、
  看不出来，但极细的动作边缘可能慢半拍），回读失败时退回包围盒（内缩 15%）语义 —— 宁可多挡一点，
  也不能让形象点不动。（当前形象是 4068×4068 的正方形，在 320×460 的窗口里只占下面 320 px，
  上面那 140 px 整块是空的且可穿透。想贴合可以把 `window.height` 改成 340。）
- 切换形象会重建整个 Pixi 应用（连带一个新的 WebGL 上下文）。仓库里现在只有一个形象，
  这条路径实际用不上；要更低只能把贴图再降一档或改成复用同一个 Pixi 实例。
- 套用的表情不会持久化，也不会跨形象保留：点「重新加载形象」或「切换形象」都会重建渲染器，
  表情随之回到默认（菜单里的勾会一起清掉，不会再停在旧值上）。
- **`戴帽子` 在当前形象里看不出效果**，这不是实现的锅：那个 exp3 只把 `ParamCheek44` 挪 -3，
  而这个参数的量程是几千（实测基准值 -7758，且待机动作还在推它）。
  用库原本的 `model.expression('戴帽子')` 走一遍，画面差异同样只有动画噪声量级。
  所以看到「勾上了但画面没变」先想想是不是这类表情，不必怀疑链路 —— 要改得动模型文件。
- **表情的强弱差别很大**：`手敲琴` 会整张桌子换成小木琴，`墨镜`/`猫猫贴纸` 一眼可见，
  而 `戴帽子` 这种就是上面那条。挑表情做触发规则时值得先手动过一遍。
- 表情层**不做淡入淡出**（刻意，见「表情与触发」）：切换是瞬时的。库自带 1 秒过渡，
  但那套是单槽语义，换成可叠加之后宁可不要。
- 表情分层的通道表是**按当前形象的表情名写的**：换个形象后表里没有的名字会落到 `misc` 单槽，
  仍能用（不会再出现「点了没反应」），但叠不起来。要分层得往 `CHANNEL_OF` 里补名字。
- 敲琴要形象窗口拿到键盘焦点才收得到键：点到别的窗口就按不动了（琴还挂着），
  点回形象或从托盘重开即可。音量是现场合成的固定值，没有做音量开关。
- 聊天驱动的情绪是**本地关键词**判定，不做语义理解：「工作好累」会挂 `悲伤`（情绪优先于道具），
  但「太阳好大我快晒晕了」这种带「晕了」的句子也会命中 `晕晕`。改法在 `main/chat/emotion.ts`
  的规则表里，加一行就行。
- 闲置打盹固定 5 分钟、深夜固定 23:00–6:00，都不进配置（不想为一个还没定型的节奏加配置项）。
- **快捷输入框（`⌥⌘+←`）发的消息不会出现在已经开着的对话窗口里**：对话窗口只画自己发起的那些轮次，
  从气泡发的那一轮要关掉重开窗口才看得到（形象气泡照常会说那一句）。这是**拍板保留**的行为，
  不是漏掉的 bug：两个入口各自独立，做同步就得给对话窗口引入一套「按快照重排列表」的逻辑，
  而它的收益只是「两个窗口同时开着、又从气泡发消息」这一种用法。
- 对话期间的错误提示是「一句人话 + 厂商原文」（401 →「API Key 不对或没配」、404 →「接口地址不对」、
  429 →「请求太频繁或额度用完了」、5xx →「上游服务出错」）。状态码表在 `shared/ai.ts` 的
  `statusHint()` 里，加一条就行；表里没有的状态码就只透传原文。
- 只有一条连续会话（刻意如此，见「会话记忆」那问的答案），没有多会话切换；
  上下文裁剪是「从最早的整轮消息开始丢」，不做摘要压缩。存盘上限 1000 条，
  超了也是丢最旧的。发多少上下文由 `ai.contextLimit` 控制（默认 20 条）。
- **陪玩的那几轮不在存盘历史里**（点单、猜数字、猜拳…）：它们只活在内存与界面上，
  重启后对话窗口里看不到玩过的那几局。要留痕也可以，但那意味着把「user: 石头」写进磁盘，
  而它本来就不该进上下文（见「陪玩」那一节）—— 记进来只会让下次的上下文多一堆没法用的东西。
- 闲聊的节奏不进配置：碎碎念 30–60 分钟、梦话随打盹、打盹 5 分钟、睡前那句 45 分钟冷却，
  都是模块常量（和「闲置打盹固定 5 分钟」同一条理由：不想为一个还没定型的节奏加配置项）。
  想调就改 `smalltalk.ts` / `idle.ts` 顶上的常量。
- 点单是**关键词**触发的：短句里出现「奶茶」就会换脸，不判断你是不是真的在下单。
  词表在 `play.ts` 的 `FACE_TABLE` 里，加减都是改一行。
- Live2D 只支持 Cubism 4/5（`.model3.json` + `.moc3`），Cubism 2.1 未接入。
- **选项气泡只在三处出现**：陪玩邀请、猜拳每回合、午饭问句。晚饭/下班那句仍是陈述（没给按钮），
  其他闲聊问句也还没铺 —— 想加一处，就是在说得那句话后面补一次 `showAsk`（见 `ask.ts`）。
- 猜拳按钮 20 秒没人点就自己收掉，但**那一局还在等你**：接着打字出拳照常接得住，
  不会因为按钮没了而卡住（下一回合又会挂上）。
- 午饭问句固定是「吃了没？+ 吃了 / 还没」，两句回话是预设的；这条走的是「碎碎念」的闸门
  （可见 / 在场 / 不忙 / 不静音都满足才说），并在当天只问一次。
- **长期记忆的三条上限都不进配置**：日记时刻固定 23:30–23:59、`memory.md` 60 行、摘要 ≤5 条/天
  （和「闲置打盹固定 5 分钟」同一条理由：不想为一个还没定型的节奏加配置项）。
- 记忆是**全文注入**、没有检索：60 条就是每轮都带着的常驻成本（几百 token）。
  要更省就编辑文件删几行 —— 上限存在的意义就是让它有头。
- 「记住」只认**开头**（`记住：…` 或 `记住 …`）；句中出现「记住」不触发。单条最长留 300 字。
